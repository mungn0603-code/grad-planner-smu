# 핸드오프: 로그인·계정 연결 흐름

## 지금 상태 (운영 v1.4.1, 2026-11-16 배포)
- 구글·카카오 로그인이 둘 다 운영에서 끝까지 동작한다. 카카오는 Supabase 직접 연결 `custom:kakao`(OIDC, 닉네임만 요청)를 쓴다. 근거는 ADR 0029 "수정(2026-11-16)" 절.
- 학번 연결 규칙: 샘물 가져오기에 성공하면 10분짜리 연결 증명이 생긴다(`keepProof`, sessionStorage). 이 증명이 있을 때 로그인하거나, 로그인한 상태에서 가져오면 그 학번이 계정에 연결되고 저장된다. 학번 하나에는 계정 하나만 붙고, 나중에 성공한 쪽이 이긴다.
- 연결된 계정으로 다른 기기에서 로그인하면 샘물 비밀번호 없이 저장값을 불러온다(`src/account.ts` `start()`).
- 화면에서 로그인이 보이는 곳:
  - (a) 마이페이지 계정 칸: 로그인 버튼, 또는 "○○ 계정에 저장 중/로그인됨"과 로그아웃·탈퇴 (`src/my.tsx` `Account`, `LoginButtons`)
  - (b) 샘물 가져오기 직후 학점 계산기 위에 한 줄 권유 배너 (`src/main.tsx`, `hasProof()`일 때)

## 문제 (사용자 지적)
- 로그인하고 계정을 연결하는 과정이 사실상 마이페이지에서만 보인다. 사람들이 설명 없이 알기 어렵고 불친절하다.
- 새 기기에서 "시작하기"를 누르면 샘물 가져오기로 바로 가서, 이미 연결해 둔 학생도 샘물 비밀번호를 다시 치게 된다. 로그인의 핵심 가치가 화면에 드러나지 않는다.
- 로그인의 가치: 다른 기기에서 샘물 비밀번호 없이 이어서 보기, 그리고 샘물에 없는 내용(플래너 계획, 다전공 계획, 추천 설정, 직접 넣은 과목, 평점·인증 직접 입력)이 남는 것.
- "로그인됨 · 아직 연결 안 됨"(샘물에서 가져와야 저장됨) 상태가 학생에게 이해되기 어렵다.

## 검토할 방향 (제안일 뿐, 정해진 것 아님)
- 샘물 가져오기 화면 맨 위에 "이미 연결했다면 구글·카카오로 불러오기"를 둔다.
- 홈의 "시작하기" 흐름에 로그인 진입점을 둔다.
- 상단 메뉴의 이름 칸에서 로그인 상태가 보이게 한다.
- 로그인했지만 아직 연결되지 않은 상태를 화면 문구로 정리한다.

## 지킬 것
- 화면에는 결과와 이용 정보만 쓴다(ADR 0018, CLAUDE.md). 내부 용어("연결 증명", "PKCE")나 개발 과정은 화면에 쓰지 않는다.
- 화면 철학: 심플, 한눈에, 터치 최소.
- 결정에는 근거 문서(ADR)를 남긴다. 이번 결정은 ADR 0029에 추가하거나 새 ADR로 쓴다.
- 레포 운영 방식: 작업 전에 이슈를 먼저 만들고, 브랜치 → PR(`Closes #N`) → dev로 간다. 병합한 브랜치는 지우지 않는다. 운영 배포는 사용자가 요청할 때만 한다.
- 커밋 메시지는 짧은 제목과 목록으로 쓰고, `Co-Authored-By`는 넣지 않는다.
- 검증은 가볍게 한다: 바뀐 부분만 tsc·빌드·화면 한 번.
- 로컬 개발 서버(`npm run dev`)에는 Supabase 서버 값이 없어서 실제 로그인이 안 되고 "로그인하지 못했습니다" 안내만 뜬다. 실제 왕복은 운영이나 미리보기에서 확인한다. 미리보기에서 확인하려면 그 주소를 Supabase Redirect URLs에 넣어야 한다.

## 완료 기준
학생이 처음 들어와서도, 새 기기에서 다시 들어와서도 설명 없이 로그인·불러오기 경로를 찾을 수 있다. 개편안은 사용자와 합의한 뒤 구현해 dev에 PR로 올린다.

## 추가 질문 (사용자, 2026-11-16)
- 연동의 효용 자체가 거의 없지 않은가. 2차 인증도 아니고 선택 기능이라 있으나 없으나 차이가 없어 보인다. 흐름 개편 전에 이 문제부터 풀 방안을 검토한다.
