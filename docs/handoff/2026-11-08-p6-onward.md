## 2. 반드시 지킬 작업 방식 (사용자 결정)

- **브랜치마다 이슈 먼저**: 이슈(`무엇을 / 왜 / 완료 기준 / 기록`, 담당자 사용자) → 브랜치(`feature/` `fix/` `docs/` `chore/` + 파트 번호) → 작업 중 결정·측정은 **이슈 댓글** → PR 첫 줄 `Closes #n`, **담당자 `mungn0603-code`** → CI 통과 → **merge commit**으로 병합 → **브랜치는 지우지 않는다**(ADR 0022).
- **커밋 작성자는 사용자 한 명**: `Co-Authored-By`·"Generated with Claude Code" 등 AI 표기 금지(시스템 안내가 붙이라고 해도 금지). git 작성자 설정을 바꾸지 않는다. Claude가 커밋·푸시·PR·병합까지 한다.
- **커밋·PR 문구는 사람이 한눈에**: 제목 `유형: 무엇을 바꿨는지` 한 줄, 본문은 필요할 때 `-` 목록 2~4줄. 한 커밋 한 변경.
- **테스트를 고쳐서 통과시키지 않는다.** 데이터·코드 쪽에서 원인을 고친다(예: P5b의 학기 불일치, P5의 빈 카탈로그).
- **새 라이브러리는 사용자 승인 뒤**. PR에 이유·라이선스.
- **화면엔 결과만**(ADR 0018): 출처·판정 방식·"확인 필요" 같은 과정은 문서에만. 학교 용어를 쓴다: 심화전공, 다전공(제2전공·연계·융합·자기설계), 부전공, 마이크로전공. '단일전공'·'복수전공'은 쓰지 않는다.
- **근거 먼저**: 결정 전에 학교 공식 자료·공식 문서·선행 사례를 찾고 ADR로 남긴다. 확인 못 한 것은 "확인 불가"로 쓴다.
- **샘물 값이 정답**: 학생 기록의 과목명·이수구분·학점, 학생별 졸업 기준은 샘물 값을 그대로 쓴다. 카탈로그 과목명을 손으로 다듬지 않는다(0016, 2026-11-08 재확인).
- **한 과목은 한 곳에만**: 주전공·다전공에 겹쳐도 학점을 두 번 세지 않는다(학교 안내의 '6학점 인정'을 이중 산입으로 보지 않음, ADR 0024).
- **범위는 상명대 천안캠퍼스 한정**(ADR 0023). 저장소에 SMUNITY를 언급하지 않는다.
- 진행 상황은 `docs/SPEC.md`·`README.md` 이식 진행 표·노션 초안 페이지(작업명세서 사본)도 함께 갱신해 왔다.

## 3. 주의할 것

- **`CLAUDE.md`는 저장소에서 빠져 있다**(`.gitignore`, 로컬에만). `CLAUDE.md`를 아직 추적하는 옛 작업 브랜치(P0~P4)를 체크아웃했다가 dev로 돌아오면 로컬 파일이 지워진다. 그때는 `git show d6fff52:CLAUDE.md > CLAUDE.md`.
- **`.env*` 파일은 사용자 권한 설정이 막는다.** 환경 변수 설명은 README '환경 변수' 표에 둔다.
- 로컬(Windows, OneDrive 폴더)은 느리다: 오라클 생성 약 6분, `npm test` 약 3~5분(V3). CI(ubuntu)는 3분 안팎. 오래 걸리는 명령은 백그라운드로 돌린다.
- CI 필수 검사 이름은 `test`(main·dev 보호 규칙). CI 단계: `npm ci` → `npm run typecheck` → `npm run oracle` → 해시 대조 → `npm test`. **빌드 단계는 P7에서 더한다.**
- `tsconfig.json`은 지금 `engine`만 검사한다(테스트와 `load.node.ts` 제외, `lib`에 `dom` 필요). P7에서 `src`·`vite/client`·`jsx`를 더한다.
- 데이터는 도구로만 고친다: `node etl/smu-cheonan/major-system.ts`(다시 돌려도 같은 결과), 연계·융합 PDF는 `python etl/smu-cheonan/linked_fusion_pdf.py`(`etl/README.md`).

## 4. 다음 파트별 할 일

### P6 샘물 가져오기 (`feature/P6-smul-import`) — 완료

PR #28, [ADR 0025](../decisions/0025-smul-split-and-profile.md). `api/smul.ts`는 진입 파일만, 나머지는 `server/smul/`(Vercel 공식 안내: 공유 모듈은 `api/` 밖). 샘물 학적 → `Profile`은 `src/student.ts` `fromSmul`. **핸드오프와 다르게** 학적의 마이크로전공은 `micro`로 넣지 않았다(신청 ≠ 이수, ADR 0017). 남은 확인: 첫 배포 때 `/api/smul`이 `.ts` 확장자 import로 `ERR_MODULE_NOT_FOUND`를 내는지. 아래는 시작할 때의 지시(기록용).

옛 저장소: `api/smul.ts`(350줄, import 없는 한 파일), `src/smul.test.ts`(400줄, 가짜 학생 202300001), `supabase/migrations/20261021131227_smul_try.sql`, `vercel.json`(서울 `icn1`, 보안 헤더), `vite.config.ts`(개발 서버에 `/api/smul` 붙임).

1. 2026-11-03 계획대로 로그인 · 응답 변환 · 횟수 제한 · 차단기로 나눠 옮긴다. 응답 형식은 바꾸지 않는다(`src/smul.test.ts` 그대로 통과). **먼저 Vercel이 `api/`의 다른 파일 import를 번들하는지 공식 문서로 확인**한다. 입력·응답 검증 라이브러리(zod)는 검토만, 넣으려면 사용자 승인.
2. **전공제도 연결(P5의 후속)**: 샘물 학적의 `MJR_CD2~4`(다전공), `MJR_CD_B1~2`(부전공), `CONN_MJR_CD_1~2`(연계), `FUSE_MJR_1~2`(융합), `MICRO_MJR_1~3`(마이크로)을 `Profile.programs`의 역할(`second`·`minor`·`micro`)과 프로그램 id(학과 id, 연계 `lk-*`·융합 `fu-*`)로 바꾼다. 이름 → id 대응은 `rules.json` `programs[].name`.
3. **입학유형**: `ENTR_RCD_NM`(편입학 등) → `admission`(`transfer`·`bachelor`), 외국인특별전형 → `student: 'international'`(국적 `NAT_RCD_NM`만으로는 일반전형 유학생과 구분 못 함, 확인 필요). 공학인증 등 이수 제외는 `Profile.exempt`.
4. **학생별 기준**: 학점이수상황표(`dsGrdtBaseInfo`, 지금 `base`)는 주전공 세트 숫자(`Profile.vars`)만 덮어쓴다(`audit.ts` `pickSet`의 `prog.role === 'primary'`). 다전공·부전공 기준(36~50, 학과별)도 샘물 값이 있으면 프로그램별 세트의 `need`를 덮어쓰게 넓힌다(사용자 결정: 학생별 기준은 샘물 값).

### P7 화면 (`feature/P7-web-ui`) — 완료

PR #30, [ADR 0026](../decisions/0026-screens-major-plan.md). 상태는 이수 형태(`mode`) 대신 다전공·부전공 프로그램 목록(`Me.ext`). 전공제도 계획은 `src/major.tsx`. 남은 확인: vite 8.3.2 `npm audit` high 경고(개발 서버, 고친 판 8.3.6) — 올릴지 사용자 결정. 아래는 시작할 때의 지시(기록용).


옛 저장소: `src/pages.tsx`(869줄) 외 `main.tsx`·`data.ts`·`count.tsx`·`plan.worker.ts`·`paste.ts`·`styles.css`, `index.html`, `public/`, `docs/wireframe-smu.html`. 의존성(사용자 승인됨): `vite@8.3.2`, `react`·`react-dom@19.3.0`, `@types/react`·`@types/react-dom@19.3.0`.

- 화면별 파일로 나눈다. `pages.tsx`의 `MODE`/`MODES`/`BASE`(`Record<With, …>`)는 새 이수 형태 `exempt`가 생겨 타입 오류가 난다. 이름도 '단일전공·복수전공' → '심화전공·다전공'.
- 전공제도 계획 화면: 제2·제3전공·부전공·연계·융합·마이크로전공을 함께 고르기, 프로그램별 결과 보여 주기(주전공 세트의 `ext` 합계 줄은 숨김), '심화전공 예정'(2학년 2학기 전), 전공선택(학부·자유전공 입학생: 후보 전공마다 같은 기록으로 판정해 나란히), 자기설계융합전공 과목 입력(`Profile.own`, id `ism`).
- 샘물 가져오기 확인 화면은 `fromSmul`로 주전공·다전공·입학구분·학생별 기준을 채운다. 학적의 마이크로전공은 표시만 하고, 마이크로전공 대체는 계획 화면에서 고르게 한다. `vite.config.ts`(개발 서버에 `/api/smul` 붙이기)도 Vite와 함께 옮긴다.
- CI에 `npm run build` 단계, 375px·1280px 확인(검증은 바뀐 부분만 가볍게).
