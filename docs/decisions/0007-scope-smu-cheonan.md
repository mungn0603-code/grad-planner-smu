# 0007. 범위를 상명대 천안캠퍼스로 줄여 먼저 완성

- 상태: 채택 (2026-10-21, 사용자 결정)
- 관련: `docs/superpowers/specs/2026-10-21-smu-cheonan-redesign-design.md`, `docs/wireframe-smu.html`, [`ARCHITECTURE.md` §11](../ARCHITECTURE.md)

## 맥락

처음 범위는 서울 주요대 + 지방거점국립대였다. 0001~0005로 엔진과 데이터 구조는 여러 대학에 맞게 만들었지만, 대학마다 데이터 수집·검토 비용이 크고(0001), 실제 사용자와 학교 허가가 있는 곳은 상명대였다.

## 결정

- **상명대 천안캠퍼스 하나만 완성한 뒤 확장 계획을 세운다.** 대학 선택 UI를 없애고, 데이터 묶음도 `data/smu-cheonan/`만 번들에 넣는다.
- 다른 대학 데이터와 엔진의 다대학 구조는 지우지 않는다(확장 때 되살림).
- 화면은 상명대학교 UI(시그니처 로고, SM Blue `#0E207F`, 천안캠 사진)를 바탕으로 상단 메뉴 + 사진 배너 + 흰 본문 구성으로 바꾼다. 와이어프레임을 먼저 확정한 뒤 구현한다.
- 입력 경로는 샘물 가져오기·과목 검색·직접 입력만 남긴다(북마클릿·붙여넣기·백업은 코드까지 삭제).
- 단계: 1단계 화면 + 기기 저장(완료), 2단계 회원제·서버 저장(0011).

## 근거

- **사용자 결정**(2026-10-21): "상명대 천안캠퍼스만 완성한 뒤 확장 계획".
- 학교 공식 허가(상명프렌즈 융합혁신대학, 2026-10-21)가 있어 학교 자료(로고·사진·전용색)와 샘물 연동을 쓸 수 있다(허가 범위에 샘물 운영 부서가 포함되는지는 미확인).
- 이 프로젝트는 천안 AX 개인 과제와 상명프렌즈 결과물로 제출한다. 완성도 있는 한 학교 서비스가 여러 학교의 미완성 서비스보다 결과물로 낫다는 판단이다.

## 벤치마킹

- 대학별 졸업요건 서비스 조사(2026-10-21): 명지대·동국대·GIST·세종대·수원대·광운대 등 학생 서비스는 **모두 한 학교 전용**이었고, 여러 대학을 한 엔진으로 다루는 곳은 찾지 못했다. 한 학교를 깊게 완성하는 것이 실제 사례의 일반적인 출발점이라는 근거로 썼다. 가져오기 방식은 성적표 PDF·엑셀 업로드, 브라우저 확장, 포털 로그인으로 나뉘었다(0008).

## 결과·한계

- 다른 대학으로 넓힐 때는 0001의 구조를 그대로 쓰되, 데이터 수집·검토 비용과 학교별 연동 허가가 다시 필요하다.
- 다크 모드, 에브리타임, 통계, 이메일 발송, Q&A는 이번 범위에서 뺐다.
