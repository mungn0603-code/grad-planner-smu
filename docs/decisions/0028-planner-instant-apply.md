# 0028. 학점 플래너: 바로 반영, 기본은 지금 전공제도, 후보 전공은 그 학과 과목만

- 상태: 채택 (2026-11-08, 사용자 피드백)
- 관련: [0018](0018-user-facing-copy.md)(화면 문구), [0026](0026-screens-major-plan.md)(전공제도 계획 화면), 이슈 #42

## 맥락

사용자 피드백: 계산은 맞지만 화면이 전문적으로 보이지 않고, 플래너에서 조건을 고른 뒤 '반영하기'·'추천받기'를 한 번 더 눌러야 한다. 전공제도 '종류'는 늘 제2·3전공으로 열려 학생의 지금 상태와 맞지 않았다. 후보 전공 비교는 다른 학과에서 전공 이수구분으로 들은 과목까지 후보 학과의 전공 학점으로 셌다. 사용자 원칙: 간단하게, 한눈에, 여러 번 누르지 않게, 세련되게.

## 결정

| 항목 | 어떻게 |
|---|---|
| 바로 반영 | 학점 추천 조건(계절학기·초과 신청·SM-CDR 트랙·전공제도·마이크로전공)과 전공제도 계획은 바꾸는 즉시 저장한다. 추천은 기존 Worker 250ms 지연 뒤 다시 푼다. 확인 버튼은 없앴다. 계획을 지울 때만 '내 전공제도로 되돌리기' |
| 기본값 | 계획이 없으면 학생의 지금 다전공·부전공(샘물 학적 또는 직접 입력)으로 계산하고, 종류 고르기도 그 종류로 연다. 없으면 심화전공. 학적의 마이크로전공은 신청이라 넣지 않는다(0025와 같은 규칙) |
| 계획 탭 결과 | 계획을 고르기 전에도 지금 전공제도의 졸업요건을 바로 보인다 |
| 후보 전공 비교 | 후보 학과 교육과정(모든 판)에 전공 이수구분으로 있는 과목만 전공으로 세고, 그 밖의 전공 이수구분 과목은 일반선택(일선)으로 옮겨 판정한다(engine `reassign`) |
| 문구 | 제한은 행동으로: '다전공 최대 2개 선택', '마이크로전공 최대 3개 선택', '후보 전공 최대 3개 선택' |
| 시각 | 설정은 한 판 안의 줄(왼쪽 이름·오른쪽 칸), 종류는 누르는 버튼, 추천 요약은 판정 한 마디 + 숫자 셋, 학기 카드는 담은 학점 막대와 이수구분 색(주전공·다전공·마이크로전공·교양). 학기 카드는 모두 펼친 채로. 글꼴 Pretendard |

## 근거

- 즉시 반영: 계산이 기기 안 Worker라 다시 푸는 비용이 작고(수백 ms), 바꾼 결과가 바로 보이는 쪽이 확인 단계보다 누르는 횟수가 적다. 사용자 결정.
- Pretendard: 한국어 UI용 오픈소스 글꼴(SIL OFL-1.1, github.com/orioncactus/pretendard). 원래 쓰던 Noto Sans KR(Google Fonts)처럼 외부에서 불러오며 CSP의 `style-src`·`font-src`를 jsDelivr로 바꿨다. 사용자가 오픈소스 활용을 요청했다.
- 후보 전공: 사용자 지적(본인이 들은 과목이 그 학과 전공으로 인정되는지). 학교 전공선택 안내(smu.ac.kr majorChoice)에 학점 인정 규칙은 없어 교육과정 소속으로 판단했다.

## 검토한 대안

| 대안 | 미채택 이유 |
|---|---|
| 확인 버튼 유지 | 사용자 원칙(여러 번 누르지 않게)과 맞지 않음 |
| 학적의 마이크로전공도 기본 계획에 넣기 | 신청만으로는 다전공·심화전공을 대신하지 않아(학사안내) 계산이 달라진다 |
| 후보 학과 과목을 일반선택으로 들은 경우 전공으로 옮기기 | 전공 확정 뒤 이수구분 정정이 되는지 확인 불가 |
| UI 라이브러리(shadcn/ui 등) 도입 | Tailwind·새 의존성이 필요하고 화면 전체를 바꿔야 한다. 지금 CSS로 충분 |
