# 0008. 샘물 수강 기록 가져오기: 직접 로그인 → 서버 중계 로그인(학교 허가)

- 상태: 채택 (2026-10-21, 사용자 결정·학교 허가). 2026-10-20의 "서버가 비밀번호를 받지 않는다" 결정을 샘물에 한해 대체
- 관련: `api/smul.ts`, `src/pages.tsx` `SmulLogin`, [`ARCHITECTURE.md` §6-2~§6-5](../ARCHITECTURE.md)

## 맥락

졸업요건 판정에는 학생의 이수 과목(학수번호·과목명·이수구분·학점·성적·학기)이 필요하다. 상명대 통합정보시스템(샘물)에는 공개 API가 없고(웹 검색, 학교 내부 제공 여부는 확인 불가), 화면은 eXbuilder6라 `<table>`이 없어 표 복사도 되지 않는다(§6-3).

## 결정 경위

| 날짜 | 방식 | 이유 |
|---|---|---|
| 2026-10-20 | **직접 로그인 + 북마클릿**: 학생이 샘물에 직접 로그인한 브라우저에서 북마클릿이 학생 세션으로 성적·수강 요청을 보내 허용 열만 앱으로 넘김. 서버 대리 로그인 시험 코드는 삭제 | 비밀번호를 받지 않는다. 샘물의 "1 PC 1 USER"(서버 로그인이 학생 세션을 끊음)와 매크로 IP 차단 공지(모든 요청이 같은 서버 IP에서 나감) 때문 |
| 2026-10-21 오전 | 로드맵: ① 성적증명서 PDF·캡처 업로드 ② 확장·앱 내장 브라우저 ③ 학교 직접 전송(API·전송요구권) | 사용자 브라우저 시험에서 북마클릿이 확인 창을 띄우지 못함(원인 미확정) |
| 2026-10-21 | **서버 중계 로그인**: 학생이 학점플래너에 학번·샘물 비밀번호를 넣고, 서버가 그 요청 안에서만 샘물에 로그인해 수강 기록을 가져옴. 저장하지 않음 | 사용자가 상명대(상명프렌즈 융합혁신대학) 공식 허가를 받음. 학생 입장에서 가장 단순한 흐름 |

## 이 방식의 정확한 성격

학생이 직접 입력하지만 **샘물에 실제로 로그인하는 주체는 우리 서버**다. 그래서 "학생이 입력한 계정으로 서버가 샘물에 로그인하는 중계 방식(비밀번호 비저장)"이다.

| 방식 | 비밀번호가 거치는 곳 | 샘물이 보는 접속 주체 | 예 |
|---|---|---|---|
| ① 직접 로그인 | 학생 브라우저 → 학교 | 학생 기기 IP | 북마클릿, 브라우저 확장, 앱에서 직접 로그인 |
| ② 서버 중계(우리) | 학생 → 우리 서버 → 학교, 저장 안 함 | 우리 서버 IP | `api/smul.ts` |
| ③ 보관 후 대리 | 업체가 저장해 두고 반복 로그인 | 업체 서버 IP | 예전 금융 스크래핑 |

## 근거

- **사용자 결정·학교 허가**(2026-10-21). 허가 범위에 샘물 운영 부서가 포함되는지, 허가 문서 보관은 미확인.
- **측정**: 가짜 샘물로 요청 순서·쿠키 전달·본문·허용 열 걸러내기·401 판정을 시험한다(`src/smul.test.ts`). 요청 구조는 §6-3에서 학생이 직접 로그인한 실제 세션으로 확인했다. **실제 샘물 계정으로 서버 가져오기는 확인 불가**(학생 본인 계정 필요).

## 결과·한계

- 남는 위험: 서버가 입력자가 학번 주인인지 알 수 없어 "학번·비밀번호가 맞는지 알려 주는 창구"가 된다. 모든 요청이 서버 IP 하나로 나가 남용 한 번에 학교가 서버를 막을 수 있다. 남이 틀린 비밀번호로 학생 계정을 잠글 수 있다(샘물 5회 실패 잠금). → 0010.
- 1 PC 1 USER: 가져올 때마다 학생의 다른 기기 샘물 세션이 끊긴다. 화면에서 안내한다.
- 2단계 회원제(0011)의 가입·재설정도 같은 로그인을 쓰므로 같은 방어를 처음부터 건다.
