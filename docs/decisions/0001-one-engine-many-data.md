# 0001. 엔진 하나 + 대학별 데이터

- 상태: 채택 (2026-10-20)
- 관련: `engine/`, `data/<univ>/`, [`ARCHITECTURE.md` §0·§1·§2](../ARCHITECTURE.md)

## 맥락

출발점은 상명프렌즈 학점플래너(claude.ai 아티팩트 V44)였다. 이 앱은 상명대 그린화공 전용 HTML에 문자열 치환 197곳을 6단계로 적용해 다른 학과용을 만들었고, `IS_GREEN` 분기가 약 30곳, 전역 가변 상태가 약 20개였다. 학과·대학을 늘릴수록 분기와 치환이 늘어나는 구조였다.

## 결정

대학·학번·학생 유형은 **엔진 하나와 데이터**로 다룬다. 학교별 엔진은 만들지 않는다. 학교마다 다른 것은 "요건 데이터"이고, 풀어야 하는 문제의 종류(요건 판정, 학기 배치)는 같다고 본다.

## 근거

- **측정**: 같은 엔진으로 상명 천안 40개 학과(3,700개 사례), 외부 대학 2곳(연세대 컴퓨터과학과 2026, 충남대 컴퓨터인공지능학부 2026)을 판정했다. 외부 대학을 넣을 때 엔진 변경은 학수번호 모양 태그(`codeTags`) 3줄뿐이었다(V2, 골든 8/8).
- **측정**: 2027판 교육과정(과목명 변경·분리·학점 변경·신설), 2027 요건, 2021 과거 판을 데이터만으로 추가했고 엔진은 고치지 않았다(V4, 8/8).
- 확장 비용의 대부분이 엔진이 아니라 데이터 수집(외부 대학 1개 학과 약 45~50분, 사람 검토 전)이라는 점도 측정했다. 엔진을 늘리는 구조였다면 이 비용 위에 코드 비용이 더해진다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 기존 앱 구조 유지(학과별 치환·분기) | 분기 수가 학과 수에 비례해 늘어나고, 시험이 0개라 회귀를 막을 수 없다. 기각 |
| 대학마다 엔진(어댑터 코드) | 대학 수만큼 같은 판정 로직을 다시 쓴다. 요건의 차이가 데이터로 표현되는 한 필요 없다. 기각 |

## 결과·한계

- 대학 추가 = `etl/<univ>/` 변환 + `data/<univ>/` 파일 + 골든 시험. 엔진 검사(`engine/check.ts`)와 골든을 통과해야 배포한다.
- 데이터로 표현되지 않는 요건이 나오면 규칙 종류를 늘려야 한다(0002의 '아직 넣지 않은 것').
- 2026-10-21 범위를 상명 천안으로 줄였지만(0007) 엔진의 다대학 구조와 외부 대학 데이터는 지우지 않았다.
