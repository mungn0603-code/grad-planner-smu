# 0009. 비밀번호 비저장, 허용 열만 반환, 로그에 개인정보 없음

- 상태: 채택 (2026-10-20 원칙, 2026-10-21 서버 함수에 적용)
- 관련: `api/smul.ts`(`toRows`, `student`, `wrap`), `src/pages.tsx` `TERMS`, [`ARCHITECTURE.md` §6-3·§6-5](../ARCHITECTURE.md)

## 맥락

샘물 응답에는 학점 계산에 필요 없는 개인정보가 섞여 온다. 수강신청현황 행에는 이름·연락처·이메일·성별·학번·담당교수 연락처가, 학생 정보에는 이메일·연락처가 함께 온다(§6-3에서 실제 세션으로 확인). 서버 중계 로그인(0008)이라 비밀번호도 서버를 지난다.

## 결정

- **비밀번호**: 요청 하나 안에서만 쓰고 저장·기록하지 않는다. 화면도 컴포넌트 상태에만 두고 받은 뒤 비운다(localStorage에 넣지 않음).
- **허용 열(allowlist)만 돌려준다**: 이수 과목은 년도·학기·학수번호·교과목명·이수구분·학점·성적, 수강 중 과목은 학수번호·교과목명·이수구분·학점, 학생 정보는 이름·학과·제2전공 이름만. 나머지는 서버에서 버린다. 학생 검색(`/UsrStudSrh/list.do`)처럼 생년월일·계좌까지 주는 요청은 아예 부르지 않는다.
- **로그**: 실패 단계·오류 이름·건수만 남긴다. 학번·비밀번호·과목 내용은 남기지 않는다.
- **응답**: `Cache-Control: no-store`.
- **횟수 제한 기록**(0010): 학번·IP 원문 대신 HMAC 값을 쓰고 기한이 지나면 지운다.
- 이용안내(`TERMS`)에 가져오는 항목·비밀번호 비저장·시도 횟수 기록을 적고, 동의해야 가져오기를 쓸 수 있다.

## 근거

- **원칙**: 개인정보 보호법의 최소 수집 원칙(목적에 필요한 최소한만 수집, 제3조·제16조). 법률 해석·적합성 검토는 확인 불가(법률 자문 필요).
- **측정**: `src/smul.test.ts`가 가짜 응답에 넣은 이름·이메일·연락처가 결과에 없는지, 학생 정보가 `name·dept·dept2` 세 키만인지, 횟수 제한 요청에 학번·IP 원문이 없는지 확인한다.

## 결과·한계

- 학점플래너에 저장되는 것은 1단계에서는 학생 기기(localStorage)뿐이다. 2단계(0011)에서 서버 저장이 생기면 처리방침을 다시 쓴다.
- 교양영역 열(`CULT_ARA_NM`)은 값이 요건 데이터의 영역 이름과 같은지 확인 전이라 보내지 않는다.
- Vercel·Supabase 자체가 남기는 접속 로그(IP 등)는 플랫폼 정책을 따른다(우리 코드 밖).
