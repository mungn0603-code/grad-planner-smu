# 0004. 기존 앱을 정답 기준(오라클)으로 삼아 차이 검증

- 상태: 채택 (2026-10-20)
- 관련: `oracle/`(기존 앱 사본·하니스·`known-diffs.json`), `engine/v1.parity.test.ts`~`v5.swap.test.ts`, [`ARCHITECTURE.md` §7](../ARCHITECTURE.md)

## 맥락

기존 앱(V44)에는 실행 가능한 시험이 0개였고 git도 없었다. 엔진을 새로 짜면서 "새 엔진이 맞다"를 보일 기준이 필요했다. 학과별 졸업요건 정답을 사람이 손으로 수천 건 만드는 것은 현실적이지 않았다.

## 결정

- 기존 앱 스크립트를 Node `vm`으로 그대로 실행해 40개 학과, 3,700개 사례의 판정·추천 결과를 뽑고(V0), 이것을 **오라클(정답 기준)** 로 새 엔진과 비교한다(V1).
- 차이가 나면 둘 중 누가 틀렸는지 원인을 찾고, 기존 앱 버그로 밝혀진 차이는 `oracle/known-diffs.json`에 **판정 조건까지 코드로** 적는다. "설명 안 된 불일치 0"을 통과 기준으로 둔다.
- 외부 대학은 오라클이 없으므로 문서만 보고 손으로 계산한 **골든 사례**(신입 충족·부족·편입·유학생)로 검증한다(V2).
- 추천은 "최적인가"를 풀이기의 최적 증명과 평가기 재판정으로 확인한다(V3).
- 데이터 변경 능력은 판 추가 시나리오로 확인한다(V4). 같은 입력을 두 번 돌려 결과 해시가 같은지(결정성)도 본다.

## 근거

- **측정**: V0에서 40/40 학과 로드, 실제 브라우저 결과와 15/15 해시 일치. V1에서 3,700건 중 2,699건 완전 일치, 1,001건은 기존 앱 버그 2종(학수번호 같고 이름만 바뀐 과목을 '미개설' 처리, CDR·총학점 중복 기준 불일치)으로만 설명됐다.
- 이 과정에서 기존 앱 버그 5종을 찾았다([`ARCHITECTURE.md` §1](../ARCHITECTURE.md) 표). 오라클을 그대로 믿지 않고 차이를 설명하게 만든 덕분이다.

## 벤치마킹

| 사례 | 내용 | 채택한 것 |
|---|---|---|
| 차등 시험(differential testing), W. M. McKeeman, "Differential Testing for Software", *Digital Technical Journal* 10(1), 1998 | 같은 입력을 두 구현에 넣고 출력 차이를 버그 후보로 삼는 방법 | 기존 앱 ↔ 새 엔진 비교 구조. 차이를 "설명된 차이(known-diffs)"와 "설명 안 된 차이"로 나눈 것은 우리가 더한 규칙 |
| 골든 파일 시험 | 사람이 확정한 기대값 파일과 비교 | 외부 대학 V2 골든 |

## 결과·한계

- `npm test`에 V1~V5와 데이터 검사가 모두 들어 있다(V3가 약 4분).
- 외부 대학 데이터와 골든은 AI가 작성했고 사람 검토 전이다. 학교 담당자나 학생이 확인해야 정식 데이터가 된다.
- 화면(UI) 자동 시험은 아직 없다. 화면 흐름은 수동 확인만 했다.
