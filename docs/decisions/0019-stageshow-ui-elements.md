# 0019. stageshow 스킬에서 가져온 화면 요소: 남은 학점 숫자 굴리기, 스켈레톤

- 상태: 제안 (2026-11-05, 사용자 요청 "stageshow 스킬로 UI에 쓰일 만한 요소 정리해서 서비스 개선")
- 관련: `src/count.tsx`, `src/pages.tsx` `Loading`·`Reqs`, `src/styles.css` `.sk`·`.count`

## 맥락

stageshow(benjitaylor/skills, MIT)는 마케팅 페이지용 가짜 제품 화면과 커서 연출을 만드는 스킬이다. 대부분은 실제 앱에 해당하지 않는다. 스킬의 정지 화면 규칙(`references/craft.md`), 움직임 규칙(`references/motion.md`), React 부품(`kit/`)에서 실제 앱에 맞는 것만 골랐다.

## 비교

| stageshow 요소 | 우리 화면 | 판단 |
|---|---|---|
| 숫자는 `Count`로 바뀐 자리만 굴린다. 숫자가 그냥 바뀌지 않게 한다(motion.md "Every change moves") | "졸업까지 N학점 남음"은 다전공 계획·추천 설정을 바꾸면 그냥 바뀌어서 무엇이 달라졌는지 눈에 잘 안 띈다 | 채택. `Count`를 줄여 옮김 |
| 기다리는 동안 실제 내용 크기의 스켈레톤을 보인다(examples/loading) | "불러오는 중…" 빗금 상자. 내용이 오면 높이가 바뀐다 | 채택. 요약 상자 모양 스켈레톤 |
| 숫자 하나만 크게, 상태는 점과 짧은 글자로. 겹치는 테두리를 빼고 같은 말은 한 번만 | 0015에서 이미 같은 방향으로 정함 | 유지(변경 없음) |
| 오류는 원인이 된 칸 옆에, 버튼 상태는 한 자리에서(examples/form-error) | 샘물 로그인 오류는 칸 아래 한 줄, 버튼은 회전 표시 | 보류. 실패 원인이 서버 쪽이 많아 칸을 짚을 수 없다(0013) |
| 홈 히어로에 제품 데모 애니메이션(hero-demo) | 홈은 캠퍼스 사진과 "검사하기" 버튼 | 보류. kit가 lucide-react와 React 18 기준이라 의존성이 늘어난다(0006 라이브러리 최소화). 필요하면 따로 정함 |
| 커서·폰 프레임·벤토 격자·브랜드 로고 | 해당 없음 | 미채택 |

근거 정도: stageshow 문서는 실무자가 만든 스킬 지침이다. 연구 근거는 아니다. Nielsen Norman Group(nngroup.com/articles/skeleton-screens)은 스켈레톤이 로딩 중임과 곧 나올 화면 모양을 알려 준다고 하면서, 성능 개선을 대신하지는 않는다고 말한다. "덜 기다리는 느낌"에는 반대 결과도 있다(Viget 실험에서 스켈레톤 집단이 가장 길게 느꼈다는 2차 인용, 원문 확인 불가). 그래서 이 결정의 근거는 체감 속도가 아니라 내용이 올 때 높이가 덜 바뀐다는 점이다. 우리 학생 대상 실측은 없다.

## 결정

- 학점 계산기와 학점 플래너의 "졸업까지 N학점 남음" 숫자는 `Count`로 보인다. 바뀐 자리만 오른쪽부터 굴러가고, 소수점과 같은 숫자는 움직이지 않는다. 움직임 줄이기 설정이면 바로 바뀐다.
- `Loading`(데이터·졸업요건·추천 계산을 기다리는 동안)은 요약 상자 모양 스켈레톤으로 바꾼다. 큰 숫자 칸 하나, 막대 하나, 길이가 다른 줄 셋으로 이루어진다. 화면에는 글자를 쓰지 않고 `aria-label="불러오는 중"`만 단다.
- 새 의존성은 없다. kit 코드는 필요한 부분만 `src/count.tsx`로 옮기고 출처를 주석으로 남긴다.

## 남은 확인

- 바뀐 숫자가 실제로 눈에 띄는지는 학생 몇 명에게 다전공 계획을 바꿔 보게 하고 확인한다.
