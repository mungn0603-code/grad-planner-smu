# 0002. 졸업요건을 규칙 5종의 데이터(IR)로 표현

- 상태: 채택 (2026-10-20)
- 관련: `engine/types.ts`, `engine/audit.ts`, `data/<univ>/rules.json`·`sets.csv`, [`ARCHITECTURE.md` §3](../ARCHITECTURE.md)

## 맥락

기존 앱은 이수구분 문자열을 코드에서 직접 검사했고, 교양 영역 기준(4/2/3)이 코드와 엑셀 두 곳에 있어 화면과 추천에서 값이 다를 수 있었다. 0001의 "엔진 하나 + 데이터"를 하려면 요건을 데이터로 적는 공통 형식(중간 표현, IR)이 필요했다.

## 결정

- 규칙은 5종: `credits`(학점 합, 상한 `capped`), `courses`(과목 수), `all{need}`(하위 n개 이상), `check`(학생 입력값, 예: 평점·TOPIK), `use`(공유 블록 + 숫자 변수).
- 과목 조건은 학수번호·과목명 + 태그. 태그는 이수구분·교양 영역·출처(편입·학점교류)·학수번호 모양에서 계산한다.
- 버전 축은 둘: 요건은 **입학년도**로, 과목의 학점·이수구분은 **수강한 학기의 판**으로 고른다. 성적표에 적힌 값이 있으면 카탈로그보다 우선한다.
- **데이터가 없는 학번·유형은 다른 기준으로 대신 판정하지 않고 `ok:null`(확인 필요)로 보인다.** 모든 요건 세트에는 근거 문서(`src`)가 있어야 한다.

## 근거

- **측정**: 새 평가기 판정이 기존 앱과 3,700건 중 2,699건 완전 일치, 나머지 1,001건은 기존 앱 버그 2종으로만 설명됐다(V1, 설명 안 된 불일치 0). 즉 5종 규칙으로 기존 앱의 요건을 빠짐없이 표현했다.
- **측정**: 외부 대학 2곳의 신입·편입·유학생 요건도 같은 5종으로 표현했다(V2). 부족했던 것은 학수번호 단위 요건 하나였고 태그(`codeTags`)로 해결했다.
- `ok:null` 원칙은 "틀린 졸업 판정"이 "모른다"보다 학생에게 더 해롭다는 판단이다(**사용자 결정**·설계 원칙). 상명 편입생·유학생 요건은 미수집이라 지금 `ok:null`로 나온다.

## 벤치마킹

- 대학 학사 시스템의 졸업사정(degree audit)은 보통 "요건 블록 = 조건에 맞는 과목 집합의 학점·과목 수 기준" 구조다. 이 구조를 규칙 5종으로 일반화했다. 특정 제품의 형식을 그대로 가져온 것은 아니다(**기록 없음**: 결정 당시 외부 degree audit 제품과 형식 비교를 남기지 않았다).

## 결과·한계

- 아직 넣지 않은 것: 선수과목, 평점 척도 계산, 다전공 중복 인정 한도, 유학생이면서 편입생인 조합. 첫 데이터가 요구할 때 규칙이나 조건을 추가한다.
- 화면의 "인정 기준" 문구도 같은 규칙 트리에서 만든다(규칙의 `hint` 또는 필터에서 생성).
