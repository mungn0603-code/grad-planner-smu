# 0024. 전공제도 재정의: 여러 전공제도를 동시에 판정하고, 입학유형별 기준을 학교 자료대로

- 상태: 제안 (2026-11-08, 사용자 확인 대기). 첫 초안의 '6학점 중복 인정'은 사용자 결정으로 뺐다
- 관련: [`docs/SPEC.md`](../SPEC.md) '전공제도 명세', [0017](0017-what-if-mode-category.md)(마이크로전공·정정 코드), [0016](0016-smul-source-of-truth.md)(샘물 학생별 기준), [0004](0004-oracle-verification.md)(V1), 이슈 #19

## 맥락

첫 버전은 다전공을 '여러 전공을 듣는 것' 하나로만 다뤘다. 사용자 결정(2026-11-08):

1. 제3전공을 포함해 심화전공·제2전공·연계/융합전공·마이크로전공·부전공·전공선택을 모두 계산한다.
2. **한 과목은 이수구분 하나로만 센다.** 주전공과 겹쳐도 두 요건 학점을 동시에 채우지 않는다.
3. 연계·융합 교육과정은 2024~2026학년도.
4. 편입생·유학생 등 입학유형 기준은 학교 자료로 먼저 확인한다.

지금 엔진·데이터(2026-11-08 코드 확인):

- 이수 형태는 `single`·`double`·`minor`·`micro` 넷이고 학생 프로그램의 역할로 정한다(`audit.ts` `withOf`).
- 다전공·부전공 학점은 주전공 세트의 한 줄(`ext`)에서 다전공 이수구분(`2전선`·`연필`·`융선`·`1부선` 등) 학점 **합**으로만 센다. 어느 전공의 과목인지 보지 않는다.
- 마이크로전공 52개 묶음은 서로 같은 과목을 함께 셀 수 있다(0017 한계).
- 샘물에서 가져온 학생은 학점이수상황표의 학생별 기준 숫자가 학과 숫자를 덮어쓴다(0016).

## 제안

### 엔진 (학교를 모르는 일반 규칙으로)

| # | 무엇 | 어떻게 |
|---|---|---|
| E1 | **과목 배정** | 다전공·부전공 이수구분 과목을 학생이 고른 프로그램에 **하나씩만** 배정한다. 이수구분이 종류(제2전공·연계·융합·부전공)를 정하고, 같은 종류가 둘이면 교육과정(카탈로그)에 그 학수번호가 있는 쪽, 둘 다 있으면 먼저 고른 쪽. 프로그램별 세트는 자기에게 배정된 과목만 센다 |
| E2 | **묶음끼리 과목 나눠 쓰지 않기** | 마이크로전공처럼 'n개 이상' 묶음에서, 서로 같은 과목을 쓰지 않는 n개를 찾아야 충족(`all`에 `disjoint`) |
| E3 | **입학유형·제외 대상** | 입학유형에 학사편입을 더한다. 학생 정보에 '전공제도 이수 제외'(공학인증·체육특기자 등)를 표시하면 이수 형태가 '제외'가 된다. 편입·외국인특별전형은 자동 |
| E4 | **자기설계융합전공** | 학생이 승인받은 이수계획표의 과목을 넣으면 그 목록이 교육과정이 된다(다전공 36 또는 심화 75) |

기존 주전공 세트의 `ext` 줄(다전공·부전공 학점 합)은 그대로 둔다. 첫 앱 대조(V1)가 이 값을 비교하고, 프로그램별 판정이 모두 충족이면 합도 항상 충족이라 서로 어긋나지 않는다.

### 화면에서 할 것(P7)

- '심화전공 예정'(2학년 2학기 전), 전공선택(학부·자유전공 입학생): 후보 전공마다 같은 기록으로 판정해 나란히 보여 준다. 엔진은 그대로 쓴다.

### 하지 않는 것

- 공학인증 자체 요건(BSM·설계 점수 등): 천안 인증 프로그램과 학과별 기준을 찾지 못했다. 공학인증 대상자는 '전공제도 이수 제외'까지만 반영한다.
- 6학점 중복 인정: 사용자 결정 2로 하지 않는다.

## 결과·한계(예상)

- 편입생 전공 60은 서울 학사운영팀 자료 기준이다. 샘물에서 가져온 학생은 학교가 정한 학생별 기준이 덮어쓴다.
- 외국인특별전형·이수 제외 학생의 주전공 학점은 공식 자료가 없어 심화전공 숫자를 쓴다(**확인 불가**).
- 연계·융합 '영역별' 최소 학점은 교육과정표에 없어 36학점 합만 본다.
