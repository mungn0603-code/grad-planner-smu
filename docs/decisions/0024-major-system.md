# 0024. 전공제도 재정의: 학교 명세 8종을 엔진·데이터에 반영

- 상태: 제안 (2026-11-08, 사용자 확인 대기)
- 관련: [`docs/SPEC.md`](../SPEC.md) '전공제도 명세', [0017](0017-what-if-mode-category.md)(마이크로전공·정정 코드), [0016](0016-smul-source-of-truth.md)(샘물 학생별 기준), [0004](0004-oracle-verification.md)(V1), 이슈 #19

## 맥락

첫 버전은 다전공을 '여러 전공을 듣는 것' 하나로만 다뤘다. 학교 학사안내에는 전공제도가 8종이고(명세는 SPEC), 사용자 피드백으로 빠진 것이 드러났다.

지금 엔진·데이터가 하는 일(2026-11-08 코드 확인):

- 이수 형태는 4개다: `single`·`double`·`minor`·`micro`. 학생 프로그램의 역할(`second`·`minor`·`micro`)로 정한다(`audit.ts` `withOf`).
- 학과마다 이수 형태별 기준 숫자가 있다(`sets.csv`). 예: 그린화학공학과 2024~2026학번 `single` 전공 75·전공심화 15, `double` 45 + 다전공 36, `minor` 60 + 21, `micro` 60 + 전공심화 0.
- 다전공·부전공 학점은 주전공 세트 안의 한 줄(`ext`)에서 다전공 이수구분 태그(`major2`: 2전선·연필·융선·1부선 등) 학점 합으로만 센다. **어느 다전공의 과목인지는 보지 않는다.**
- 마이크로전공 2개 대체와 52개 교육과정은 0017에서 들어갔다.
- 샘물에서 가져온 학생은 학점이수상황표의 학생별 기준이 학과 숫자를 덮어쓴다(0016). 편입생처럼 예외인 학생도 학교가 정한 숫자가 그대로 들어온다.

## 빈칸 분석

| 제도 | 지금 | 빈칸 |
|---|---|---|
| 심화전공 | `single` 세트(전공심화 15) | 이름이 옛 '단일전공'. 2학년 2학기 전 '예정' 표시 없음 |
| 제2전공 | `double` 세트: 주전공 45 + 다전공 이수구분 36 | **같은 학수번호 6학점 중복 인정 없음**. 다전공 학과 교육과정을 모름 |
| 연계전공(천안 3) | 정정 코드만 다전공 태그 | 교육과정 없음 |
| 융합전공(천안 6) | 정정 코드만 다전공 태그 | 교육과정 없음 |
| 자기설계융합전공 | 없음 | 학생마다 교육과정이 다름 |
| 부전공 | `minor` 세트: 60 + 21 | 없음(학교 명세에 중복 인정 없음) |
| 마이크로전공 | `micro` 세트 + 52개 | 없음(0017) |
| 이수 의무 제외 | 없음 | 편입학자 등에게도 전공심화 15를 요구 |
| 전공선택 | 학과를 직접 고름 | 학부·자유전공 입학생의 '전공 미정' 상태 없음 |

연계·융합 교육과정표(2026 천안 PDF)는 학교 시스템이 뽑은 '전체 전공 교육과정표'로, 학과 교육과정과 같은 형식(학년·학기·이수구분·학수번호·학점·개설학과)이다. 영역별 최소 학점은 표에 없다. 과목 대부분이 참여 학과의 과목이라 주전공과 겹치는 경우가 많다.

## 제안

| # | 무엇 | 어떻게 | 엔진 변경 |
|---|---|---|---|
| 1 | 심화전공 이름 | 내부 값 `single`은 그대로 두고(테스트·데이터 보존) 화면·문서에서 '심화전공'으로 부른다. 2학년 2학기 전에는 화면에서 '심화전공 예정'으로 보인다(P7) | 없음 |

| 3 | 연계·융합 교육과정 | 2026 천안 PDF 9개 전공을 카탈로그(`gen/*.json`)와 프로그램으로 넣는다. 다전공 학과(제2전공)는 기존 학과 카탈로그를 쓴다 | 없음(데이터) |
| 4 | 이수 의무 제외 | 이수 형태에 '제외'를 더한다. 편입학자는 자동, 공학인증·체육특기자 등은 학생이 내 정보에서 표시. 세트는 심화전공 숫자에서 전공심화만 0으로 둔다(마이크로전공 세트와 같은 방식). 샘물 학생은 학교 기준이 덮어쓴다 | `withOf` 한 줄, 데이터 세트 추가 |
| 5 | 마이크로전공 | 0017 그대로. 원본 `md-2026.json`을 저장소로 옮긴다 | 없음 |
| 6 | 자기설계융합전공 | **보류**(F09 권장). 학생이 승인받은 과목 목록을 넣는 화면이 필요하다 | — |
| 7 | 제3전공(다전공 여러 개) | **보류**. 다전공별로 학점을 나누려면 정정 코드의 칸(첫째·둘째) 대응을 알아야 하는데 학교 자료로 확인하지 못했다 | — |
| 8 | 전공선택 | **범위 밖**. 학부·자유전공 입학생은 지금처럼 전공을 골라 계획한다 | — |

V1(첫 앱 대조)은 바뀌지 않는다. 첫 앱 사례는 다전공을 과목 목록 없는 가상 프로그램(`ext`)으로 넘기므로 `share2`가 붙지 않는다(`fromLegacy.ts` 72행).

## 결과·한계(예상)

- 연계·융합 '영역별' 최소 학점은 교육과정표에 없어 36학점 합만 본다(**확인 불가**).
- 이수 의무 제외 학생의 주전공 학점은 공식 자료가 없어 심화전공 숫자를 쓴다(**확인 불가**). 샘물 학생은 학교 값이 덮어쓴다.
- 6학점 상한은 다전공 하나 기준이다. 제3전공은 보류.
