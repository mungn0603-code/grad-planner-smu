# 설계 결정 기록 (Decisions)

학점플래너에서 내린 주요 결정을 하나씩 적는다. 각 문서는 **왜 그렇게 했는지(근거)**, **무엇과 비교했는지(대안·벤치마킹)**, **그래서 무엇이 남았는지(결과·한계)** 를 담는다.
형식은 Michael Nygard의 ADR(Architecture Decision Record) 구조(맥락 → 결정 → 결과)를 따르고, 근거와 벤치마킹 칸을 더했다([원문](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions)).
자세한 구현·측정 기록은 [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md)에 있고, 여기서는 결정과 그 이유만 모은다.

## 근거 표시

| 표시 | 뜻 |
|---|---|
| **측정** | 이 저장소의 시험·측정 결과(`npm test`, 오라클 비교 등). 다시 돌려 확인할 수 있다 |
| **공식 문서** | 라이브러리·플랫폼·표준 기관의 문서(Vercel, Supabase, HiGHS, OWASP, NIST 등) |
| **선행 연구·사례** | 논문, 공개 저장소의 실제 구현 |
| **사용자 결정** | 프로젝트 소유자가 대화에서 정하거나 승인한 것(날짜 표시) |
| **기록 없음** | 결정 당시 대안 비교를 남기지 않아 사후에 정리한 것. 근거가 약하다는 뜻으로 그대로 밝힌다 |

## 새 결정을 남기는 순서

1. 레퍼런스부터 찾는다: 표준(OWASP·NIST 등), 공식 문서, 논문, 같은 문제를 푼 공개 저장소.
2. 우리 안과 다른 점을 표로 비교한다.
3. 채택·미채택과 이유를 적고 사용자 승인을 받는다.
4. 다음 번호로 이 폴더에 남기고 위 목록에 한 줄 더한다. 결정을 바꾸면 옛 문서의 상태를 '대체됨(→ 새 번호)'으로 고친다.
