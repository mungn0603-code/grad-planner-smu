# 0018. 사용자 화면에는 결과와 이용 정보만

- 상태: 채택
- 근거: **사용자 결정**(2026-10-29)

## 맥락

화면 문구에 데이터 출처, 판정 방식, 확인하지 못한 점, 계산하지 않는 항목 같은 개발 과정 설명이 섞여 있었다. 학생에게 필요 없는 정보라 화면이 길고 지저분해지고 결과물의 완성도가 떨어져 보인다.

## 결정

- 사용자 화면에는 **결과**(학점·충족 여부·추천 과목)와 **이용에 필요한 정보**(어떻게 쓰는지, 학교 절차, 약관·개인정보 안내)만 쓴다.
- 과정은 쓰지 않는다: 데이터 출처·공지 번호, 판정·계산 방식, "확인 필요"·"명시 없음" 같은 검증 상태, 구현하지 않은 항목, 내부 용어(엔진, 오라클, 칸 id 등).
- 과정과 근거는 `docs/decisions`·`docs/ARCHITECTURE.md`·코드 주석에 남긴다.
- 문구는 짧게. 같은 뜻이 화면에 이미 보이면 다시 쓰지 않는다.

## 결과

- 0017 가정해 보기의 안내 5줄을 학교 절차 안내 2줄로 줄였다. 판정 근거(천안 2026학년도 마이크로전공 52개, MD 졸업 학점 인정 미확인 등)는 0017에만 둔다.
- 전체 화면 정리(2026-10-29):
  - "확인 필요", "요건 데이터 없음", "SM-CDR 안내 자료 기준", "학점 플래너 기준" 같은 출처·검증 표시를 뺐다. 지원하지 않는 학번은 "미지원"으로 쓴다.
  - 평점평균 계산 방식 설명을 빼고 결과와 "공식 평점은 샘물에서" 한 줄만 남겼다.
  - 내부 오류 문자열(`데이터 오류: …`, `추천 계산 오류: …`, HTTP 상태 코드)은 화면에서 빼고 콘솔에만 남긴다.
  - 엔진 경고의 "대응표" 같은 내부 용어를 뺐다.
  - 요건 트리 줄마다 붙던 신고 깃발을 빼고, 카드 아래 "학교 안내와 다르면 알려 주세요" 한 줄만 남겼다.
  - 샘물 서버 오류 안내(`api/smul.ts`)와 이용안내·동의 내용은 이용 정보라 그대로 둔다.
- 새 화면·문구를 만들 때 이 기준으로 고른다.
