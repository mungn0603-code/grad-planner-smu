# 0026. 화면 이식: 이수 형태 대신 프로그램 목록, 전공제도 계획 화면

- 상태: 채택 (2026-11-08, 핸드오프 P7 작업 지시)
- 관련: [0017](0017-what-if-mode-category.md)(가정해 보기·마이크로전공), [0018](0018-user-facing-copy.md)(화면 문구), [0024](0024-major-system.md)(전공제도), [0025](0025-smul-split-and-profile.md)(샘물 학적 → 학생 정보), 이슈 #29

## 맥락

- 첫 버전 화면은 `src/pages.tsx` 869줄 한 파일이고, 학생의 전공제도를 이수 형태 하나(`mode`: 단일·복수·부전공·마이크로)로 저장했다. 다전공 학과는 과목 데이터 없는 `ext` 프로그램 하나로 넣었다.
- P5(0024)부터 엔진은 학생 프로그램을 여러 개(제2·3전공·부전공·연계·융합·자기설계·마이크로) 받아 프로그램마다 판정하고, 다전공 과목을 프로그램 하나에만 배정하며, 다전공 교육과정 과목을 그 종류의 이수구분으로 추천한다. 이수 형태 `exempt`가 생겨 옛 `Record<With, …>` 표는 타입 오류가 난다.
- 핸드오프 P7: 화면별 파일, 전공제도 계획 화면(함께 고르기·프로그램별 결과·합계 줄 숨김), '심화전공 예정', 전공선택, 자기설계 과목 입력, CI 빌드.

## 결정

### 1. 상태: 이수 형태 대신 프로그램 목록

`Me.mode`를 지우고 `Me.ext`(다전공·부전공 프로그램 목록), `Me.exempt`(전공제도 이수 제외 표시), `Me.own`(자기설계 과목)을 둔다. 이수 형태는 엔진 `withOf`가 프로그램 목록에서 정하고, 화면은 그 결과를 이름으로만 보여 준다. 학생별 기준(학점이수상황표)은 `src/student.ts` `withBase`가 프로그램 목록에 맞춰 넣는다(0025와 같은 규칙).

- 샘물에서 가져오면 `fromSmul`로 채우고 고치지 않는다(샘물 값이 정답, 0016). 직접 입력하는 학생은 마이페이지에서 고른다.
- 이 저장소는 새 주소로 배포하므로 옛 저장값(`mode`)을 옮기는 코드는 두지 않았다.

### 2. 전공제도 계획 (`src/major.tsx`)

| 항목 | 어떻게 |
|---|---|
| 함께 고르기 | 종류(제2·3전공·부전공·연계·융합·자기설계)를 고르고 전공을 더한다. 다전공은 2개까지(제3전공까지, 졸업이수학점표). 마이크로전공은 3개까지 |
| 이미 들은 과목 옮기기 | 새로 고른 프로그램의 교육과정 전공 과목을 그 종류의 이수구분(`policy.assign.by`의 `cat`: 2전선·1부선·연선·융선)으로 옮긴 사본으로 판정한다. 주전공·다른 다전공·마이크로전공으로 이미 센 과목은 옮기지 않는다 |
| 추천 이수구분 | 엔진이 추천 행·바꾸기 후보에 `cat`(들을 때의 이수구분)을 함께 준다. 화면이 카탈로그 이수구분을 바꿔 쓰던 첫 버전 방식은 다전공에서 뺐다 |
| 마이크로전공 | 첫 버전 방식 그대로: 고른 것만 칸(1MD~3MD)별로 판정, 카탈로그에도 칸을 입힘(0017) |
| 프로그램별 결과 | 다전공·부전공·마이크로전공을 카드 하나씩(이름 · 종류). 주전공 세트의 다전공 합계 줄은 숨긴다. 학과를 못 찾아 `ext`로 가져온 학생만 합계 줄로 본다 |
| 심화전공 예정 | 다전공·부전공이 없는 신입생이 2학년 2학기 전(정규학기 1~3, 휴학 제외)이면 '심화전공 예정' |
| 전공선택 | 후보 전공(3개까지)마다 같은 수강 기록으로 주전공만 바꿔 판정해 졸업까지 남은 학점·전공 학점을 나란히 보인다. 다전공·학생별 기준은 빼고 학과 기준으로 |
| 자기설계융합전공 | 학교 교육과정에서 과목을 검색해 넣는다(`Profile.own`, 이수구분은 2전선으로 봄, 0024) |

### 3. 화면 파일

`main.tsx`(뼈대) · `state.ts`(상태·`toProfile`) · `ui.tsx`(작은 부품) · `home.tsx` · `join.tsx` · `reqs.tsx`(학점 계산기·요건 카드) · `plan.tsx` · `major.tsx` · `record.tsx` · `my.tsx` · `checks.tsx`(직접 입력 항목) · `run.ts`(추천 Worker). CI는 타입 검사 다음에 `vite build`를 돌린다.

## 검토한 대안

| 대안 | 미채택 이유 |
|---|---|
| `mode`를 두고 다전공 학과만 더 저장 | 제2전공 + 부전공, 제2·3전공처럼 둘 이상을 표현할 수 없다 |
| 다전공 추천 과목의 이수구분을 화면에서 다시 계산 | 엔진의 배정 규칙을 화면에 한 벌 더 두게 된다. 엔진이 이미 아는 값을 내보내는 쪽이 한 곳에서 관리된다 |
| 학부·자유전공 입학생에게만 전공선택 보이기 | 어느 학과가 학부·자유전공 입학 단위이고 후보 전공이 무엇인지 데이터에 없다(확인 불가). 비교 기능은 누구에게나 같은 방식이라 모두에게 둔다 |
| 자기설계 과목 직접 입력(교류협정대학 과목 등) | 학수번호·이수구분 규칙을 확인하지 못했다. 학교 교육과정 검색만 둔다 |
