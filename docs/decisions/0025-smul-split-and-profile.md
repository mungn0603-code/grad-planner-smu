# 0025. 샘물 가져오기 함수 나누기, 샘물 학적 → 학생 정보 연결

- 상태: 채택 (2026-11-08, 핸드오프 P6 작업 지시). 마이크로전공 처리는 아래 '핸드오프와 다르게 한 것' 참고
- 관련: [0008](0008-smul-import.md)(샘물 중계), [0009](0009-data-minimization.md)(허용 열만), [0013](0013-smul-failure-handling.md)(실패 분류·차단기), [0016](0016-smul-source-of-truth.md)(샘물 값이 정답), [0017](0017-what-if-mode-category.md)(마이크로전공), [0024](0024-major-system.md)(전공제도), 이슈 #27

## 맥락

- 첫 버전의 `api/smul.ts`는 350줄 한 파일이었다. "Vercel이 이 파일만 함수로 묶는다"는 이유로 다른 파일을 import하지 않았는데, 근거 문서는 남아 있지 않았다. 2026-11-03 계획: 로그인 · 응답 변환 · 횟수 제한 · 차단기로 나눈다. 먼저 Vercel이 다른 파일 import를 묶는지 공식 문서로 확인한다.
- P5(0024)에서 학생이 여러 전공제도 프로그램을 가질 수 있게 됐지만, 샘물 학적(다전공·부전공·연계·융합·마이크로전공, 입학구분)은 아직 `Profile`로 이어지지 않았다.
- 학점이수상황표의 학생별 기준(`base`)은 주전공 세트 숫자(`Profile.vars`)만 덮어썼다. 사용자 결정(2026-11-08): 학생별 기준은 샘물 값을 쓴다. 다전공·부전공 기준(36~50, 학과별)도 넣어야 한다.

## 조사: Vercel 함수와 다른 파일 import (공식 문서, 2026-11-08)

| 사실 | 출처 |
|---|---|
| `api/`의 지원하는 파일마다 함수가 하나씩 생긴다 | [Node.js 런타임](https://vercel.com/docs/functions/runtimes/node-js) |
| 공유 코드와 모듈은 `api/` 밖에 두고 함수 진입 파일에서 import하라고 안내한다 | 같은 문서 |
| Node.js 런타임은 진입 파일의 의존성을 빌드해 함수 하나로 묶는다 | [런타임 개요](https://vercel.com/docs/functions/runtimes) |
| 추적 도구 `@vercel/nft`는 실행에 필요한 파일을 찾고 `.ts` 파일도 추적한다 | [vercel/nft README](https://github.com/vercel/nft) |
| `/api` 안 TypeScript를 지원하고 `tsconfig.json` 옵션을 대부분 따른다(경로 매핑·프로젝트 참조 제외) | Node.js 런타임 문서 |

**확인 불가**: import 경로에 `.ts` 확장자를 쓴 경우(이 저장소는 `node --test`가 TypeScript를 직접 읽어 확장자가 필요하다) Vercel 빌드 결과가 실행되는지는 문서에 없다. 커뮤니티에 배포 뒤 `ERR_MODULE_NOT_FOUND`가 났다는 보고가 있다([Vercel Community](https://community.vercel.com/t/node-express-ts-source-somehow-being-read-as-js/4900)). 밑줄(`_`)로 시작하는 파일이 함수에서 빠진다는 문장도 찾지 못했다.

## 결정

### 1. 함수 나누기

`api/`에는 진입 파일 `api/smul.ts`(요청 검사·응답) 하나만 두고, 나머지는 `api/` 밖 `server/smul/`에 둔다. 코드는 옮기기만 하고 고치지 않았다.

| 파일 | 하는 일 |
|---|---|
| `login.ts` | SSO 로그인 → 통합정보시스템 세션, 샘물 실패 분류(`Fail`·`Kind`) |
| `parse.ts` | 샘물 메뉴 조회와 응답 변환(허용 열만), 가져오기 본체 `courses` |
| `limit.ts` | IP·학번 횟수 제한, 요청 전 검사·요청 뒤 기록, `LIMIT` |
| `breaker.ts` | 전체 차단기 상태·열기·닫기·시험 요청 |
| `store.ts` | 횟수 저장소(Supabase `smul_try`), HMAC 키 |

`store.ts`는 계획(네 갈래)에 없던 파일이다. 차단기와 횟수 제한이 같은 저장소를 쓰는데 한쪽에 두면 서로 import하게 돼서 따로 뺐다. 마이그레이션 SQL과 1:1로 맞는다.

**첫 배포 때 확인**: `/api/smul`이 `ERR_MODULE_NOT_FOUND`를 내면 TypeScript `rewriteRelativeImportExtensions`(5.7+, 출력에서 `.ts`를 `.js`로 바꿈) 또는 함수를 한 파일로 빌드하는 단계를 검토한다.

### 2. 입력·응답 검증 라이브러리(zod): 검토만, 넣지 않음

입력은 학번(숫자 9자리 정규식)·비밀번호(길이) 두 값이라 두 줄로 검사하고 있고, 응답은 서버가 고른 열로 직접 만든다. 라이브러리를 넣어 줄일 코드가 거의 없고 함수 번들만 커진다. 화면(P7)에서 응답을 읽을 때 형식 검사가 필요해지면 다시 본다(새 라이브러리는 사용자 승인 뒤).

### 3. 샘물 학적 → 학생 정보 (`src/student.ts` `fromSmul`)

서버 응답 형식(`student`·`base`)은 그대로 두고(샘물 테스트가 형식을 고정), 화면 쪽 함수가 `Profile` 값으로 바꾼다.

| 샘물 | 학생 정보 |
|---|---|
| 2전공·3전공·4전공(`MJR_CD2~4`), 연계(`CONN_MJR_CD_1~2`)·융합(`FUSE_MJR_1~2`) | `programs`에 `role: 'second'`. id는 그 역할 세트가 있는 프로그램 중 이름(`rules.json` `programs[].name`)이 같은 것(학과 id, 연계 `lk-*`, 융합 `fu-*`, 자기설계 `ism`) |
| 부전공(`MJR_CD_B1~2`) | `role: 'minor'` |
| 이름으로 못 찾은 다전공·부전공(코드 값 등) | `ext`(과목 데이터 없는 다전공). 주전공 기준(45·60)은 맞게 잡힌다 |
| 마이크로전공(`MICRO_MJR_1~3`) | 넣지 않는다(아래) |
| 입학구분(`ENTR_RCD_NM`) | '학사편입' → `bachelor`, '편입' → `transfer`, 그 밖 → `freshman`. 값이 없으면 비운다 |
| 입학구분에 '외국인'이 있거나 국적이 한국이 아님 | `student: 'international'`. 국적이 한국이면 `domestic` |
| 학점이수상황표 기준학점(`base`) | 주전공: 이수 형태별 열 → `Profile.vars`(첫 버전과 같은 대응). 다전공(연계·융합 포함): `MMJR_MJR_CDT` → 그 프로그램의 `need`, 부전공: `MINOR_MJR_CDT` → `need` |

엔진은 `Profile.programs[].vars`를 하나 더 받는다. `pickSet`이 주전공은 `Profile.vars`, 다른 프로그램은 자기 `vars`로 세트 숫자를 덮어쓴다(세트에 있는 이름만, 0016과 같은 방식). 샘물 값이 없으면 학교 자료 숫자(36·21)를 쓴다.

### 핸드오프와 다르게 한 것: 마이크로전공

핸드오프는 마이크로전공도 `role: 'micro'`로 바꾸라고 적었다. 그러나 샘물 학적의 마이크로전공은 **신청** 기록이고, 학교 기준은 2개 이상 **이수**해야 다·부·심화전공을 대신한다(0017, 학사안내 마이크로전공). 신청만으로 `micro`를 넣으면 주전공 세트가 마이크로 대체용(전공 60·전공심화 0)으로 바뀌어 전공심화가 빠진다. 첫 버전에서 같은 실수를 사람이 고친 적이 있다(명세서 '사람이 고친 사례'). 그래서 학적의 마이크로전공은 화면 표시용으로만 두고, 대체는 계획 화면(P7)에서 학생이 고르게 한다(0017 결정 그대로).

## 검토한 대안

| 대안 | 미채택 이유 |
|---|---|
| 나눈 파일을 `api/_lib/` 등 `api/` 안에 두기 | 파일마다 함수(주소)가 생길 수 있고, 밑줄 파일을 빼 준다는 문서를 찾지 못했다. 공식 안내는 `api/` 밖 |
| 한 파일 그대로 두기 | 공식 문서상 import를 묶으므로 나누지 않을 이유가 없다. 남은 위험(`.ts` 확장자)은 첫 배포에서 확인 |
| 서버가 `Profile` 값까지 만들어 보내기 | 응답 형식이 바뀌고(샘물 테스트), 서버가 학교 데이터(`rules.json`)를 읽어야 한다 |
| 학점이수상황표 `need`를 `Profile.vars` 하나에 넣기 | 다전공(36)과 부전공(21)을 함께 하는 학생은 같은 이름 `need`에 값이 둘이라 구분할 수 없다 |

## 결과·한계

- 샘물 테스트 19개를 고치지 않고 통과, 새 테스트 4개(`src/student.test.ts`). 타입 검사에 `api`·`server`·`src`를 더했다.
- **확인 불가**: 다전공 열 값이 이름인지 코드인지(실제 다전공 학생 응답 없음, 코드면 `ext`로 간다), 학사편입·외국인특별전형의 입학구분 문자열, 다전공이 둘일 때 학점이수상황표에 전공별 열이 따로 있는지(지금은 같은 값을 둘 다에 쓴다), 이수 제외 학생의 주전공 열(심화전공 열 `MJR_CDT`를 쓴다).
- 전공제도 이수 제외(공학인증 등)는 샘물에 없어 학생이 직접 표시한다(`Profile.exempt`, P7 화면).
