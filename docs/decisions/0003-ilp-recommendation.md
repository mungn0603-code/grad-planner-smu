# 0003. 학기 추천은 정수계획(HiGHS), 탐욕은 대체용

- 상태: 채택 (2026-10-20, 의존성 `highs@1.15.3` 사용자 승인)
- 관련: `engine/plan.ts`, `src/plan.worker.ts`, [`ARCHITECTURE.md` §4·§7](../ARCHITECTURE.md)

## 맥락

기존 앱의 추천(가중 탐욕)은 결과를 다시 검산하지 않았다. 처음에는 탐욕을 옮기고 검산·1과목 수리를 붙였지만, 규칙을 고칠수록 다른 사례가 깨졌다(예: 계절학기 우선 규칙을 넣자 기존 앱 대비 회귀가 4건에서 9건으로 늘었다).

## 결정

- 문제를 먼저 분류했다: **학기별 학점 상한(배낭 문제) + 여러 요건 동시 충족(집합 덮기 문제)**. 탐욕으로는 해의 존재조차 보장되지 않는 종류이고, 0002의 규칙 5종은 모두 선형 제약으로 바뀐다.
- 그래서 **정수계획으로 정확히 푼다.** 목적은 사전식 우선순위: ① 요건 부족분 ② 학기 최소학점 부족분 ③ 추천 학점 ④ 취향(계절학기·권장 학기·관심 트랙). 허용 간격 0.5로 멈춰도 ①~③은 정확히 최적이다(차이가 정수 단위라서).
- 풀이 결과는 평가기(`audit`)로 다시 판정한다. 풀이기를 못 불러오거나 1초 안에 해가 없으면 탐욕 + 1과목 수리로 대체한다.
- 브라우저에서는 Web Worker에서 푼다.
- 계절학기 추천은 학생이 켤 때만 쓰는 선택 기능으로 둔다.

## 근거

- **측정(V3, 3,700건)**: 하드 제약 위반 0, 최적 증명 3,700/3,700, 풀이기 모델과 평가기 판정 불일치 0. 기존 앱보다 나쁜 경우 0/3,120, 탐욕보다 나쁜 경우 0. 같은 입력에서 최적보다 덜 채운 비율은 탐욕 32.6%, 기존 앱 34.5%였다.
- **측정(성능)**: 계획 p50 28ms·p95 94ms, 풀이 최대 485ms. 실제 크기(후보 약 300 × 학기 15 이하)는 정수계획으로 감당된다.
- **측정(계절학기)**: 추천에서 계절학기를 빼면(표본 529건) 요건 미충족 학생이 60.3%에서 66.0%로 늘었다. 그래서 기능은 남기고 기본값은 학생 선택으로 했다.
- **공식 문서**: highs-js는 HiGHS를 WebAssembly로 컴파일한 MIT 라이브러리이고, 브라우저 화면을 멈추지 않으려면 Web Worker에서 풀라고 권한다([highs-js](https://github.com/lovasoa/highs-js)). `highs.wasm` 위치는 `locateFile`로 넘긴다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 탐욕 규칙 계속 보정 | 규칙을 고칠 때마다 다른 사례가 깨졌다(측정). 해의 품질을 증명할 수 없다. 대체용으로만 남김 |
| 다른 LP/MIP 라이브러리(glpk.js, javascript-lp-solver 등) | **기록 없음**: 결정 당시 라이브러리 간 비교를 남기지 않았다. HiGHS는 하위 의존성 없음·MIT·WASM 3.5MB라는 점으로 골랐다 |

## 결과·한계

- 첫 추천 때 `highs.wasm` 3.5MB(gzip 1.2MB)를 받는다.
- 요건을 끝내 못 채우는 학생 비율(기존 앱 59.3% → 55.5%)의 나머지는 남은 학기·넣어 둔 과목으로는 채울 수 없는 경우이고, 풀이기가 그 최소 부족분을 증명한다. "제때 졸업 위험" 안내로 쓸 수 있다.
- 추천 과목 '바꾸기' 후보도 같은 모델에서 낸다(바꿔도 부족분이 늘지 않는 과목만, `engine/v5.swap.test.ts`).
