## 맥락

기존 README는 개발자용 순서(시작하기 → 환경 변수 → 배포 → 문서 → 이식 진행)였다. 심사자·학생처럼 처음 보는 사람은 "무엇인지, 써 볼 수 있는지"를 첫 화면에서 알아야 한다. 사용자는 스타를 많이 받은 레포와 유사 서비스 레포의 README를 보고 우리에게 맞는 구성을 고르라고 했다.

## 결정

순서: **첫머리(아이콘·한 줄 소개·배지·바로 가기·휴대폰 화면) → 왜 만들었나 → 체험하기 → 기능 → 어떻게 동작하나(그림 + 정확도 근거) → 기술 스택 → 개발 → 문서**.

- 체험 계정(1001·1002, 비밀번호 1234)을 README에 그대로 적는다. immich처럼 처음 보는 사람이 샘물 계정 없이 바로 써 볼 수 있어야 한다. 이름을 바꾼 시연용 기록이다.
- 정확도 근거(오라클 3,700건 불일치 0, 최적 증명 3,700/3,700)를 표로 둔다. 유사 서비스와 다른 점이고, "계산이 맞는가"가 이 서비스의 핵심 질문이다.
- 환경 변수·배포·이식 진행처럼 개발자만 보는 내용은 `<details>`로 접는다.
- 화면 캡처는 로컬 개발 서버에서 테스트 아이디 1001로 찍었다(`docs/images/`).
