# 0027. 첫 배포: 첫 버전의 Vercel 프로젝트에 다시 연결하고, 기기 저장값을 옮긴다

- 상태: 채택 (2026-11-08 사용자 결정: 기존 프로젝트 재연결, vite 8.3.6)
- 관련: [0006](0006-web-stack-and-hosting.md)(호스팅), [0021](0021-stack-review.md)(스택), [0025](0025-smul-split-and-profile.md)(`/api/smul` 나누기), [0026](0026-screens-major-plan.md)(화면 상태), 이슈 #32·#37

## 맥락

- 학생들이 쓰는 앱은 첫 버전 저장소(`grad-planner`)를 Vercel 프로젝트 `grad-planner`로 배포한 것이었다. 전공제도 8종(0024)과 계획 화면(0026)이 학생 화면에 없다는 피드백이 있었다.
- 핸드오프는 이 저장소를 **새 Vercel 프로젝트**로 배포한다고 적었고, 0026은 "새 주소로 배포하므로 옛 저장값(`mode`)을 옮기는 코드는 두지 않는다"고 했다.
- 남은 확인 두 가지: `/api/smul`이 `.ts` 확장자 import로 `ERR_MODULE_NOT_FOUND`를 내는지(0025), vite 8.3.2의 개발 서버 high 경고(0026).

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 배포 대상 | 첫 버전 프로젝트 `grad-planner`의 Git 연결만 이 저장소로 바꾼다 | 학생이 쓰던 주소(https://grad-planner-dusky.vercel.app)에 바로 반영되고 환경 변수·Supabase를 다시 넣지 않는다 |
| 기기 저장값 | 같은 주소·같은 저장 키(`credit-planner.v1`)라 `src/main.tsx` `migrate`가 옛 값을 옮긴다: 이수 형태 다전공·부전공 → 과목 데이터 없는 `ext` 프로그램, 옛 모양 전공제도 계획은 버린다 | 옛 계획(`{mode, dept, mds}`)을 새 화면이 읽으면 `w.ext`가 없어 전공제도 계획이 깨진다. `ext`는 첫 버전과 같은 판정(주전공 45·60)을 낸다 |
| vite | 8.3.2 → 8.3.6 | 같은 8.3 판의 수정판. `npm audit` 0건 |
| 확인 순서 | PR 미리보기 배포에서 함수·화면 확인 → `dev → main` → 운영 확인 → `v1.0.0` 태그 | 미리보기에는 환경 변수가 없지만, `GET /api/smul`(405)·잘못된 학번(400)은 Supabase를 부르기 전에 답하므로 함수가 모듈까지 로드되는지 가릴 수 있다 |

## 검토한 대안

| 대안 | 미채택 이유 |
|---|---|
| 새 Vercel 프로젝트 | 새 주소를 학생에게 다시 알려야 하고 환경 변수 3개를 다시 넣어야 한다. 옛 앱이 따로 남아 두 앱이 다른 판정을 낸다 |
| 저장 키를 바꿔 옛 값 무시 | 학생이 넣은 기록·학적을 모두 잃는다 |
| 옛 마이크로전공 이수 형태도 옮기기 | 첫 버전의 '마이크로전공'은 계획에서 고른 묶음과 따로 저장돼 있지 않아 어느 묶음인지 알 수 없다 |

## 결과·한계

- 미리보기: `GET /api/smul` 405 JSON(icn1), 첫 화면 200 → 0025의 `.ts` import 위험은 없었다.
- 운영(커밋 `2b4fb76`, icn1): 첫 화면 정상(콘솔 오류 없음), `POST /api/smul` 잘못된 학번 → 400 JSON. 태그·릴리스 `v1.0.0`.
- 첫 버전에서 이수 형태를 '마이크로전공'으로 둔 학생은 심화전공으로 보이고, 전공제도 계획에서 마이크로전공을 다시 골라야 한다.
- 환경 변수는 운영(production)에만 있어 미리보기에서는 샘물 로그인이 안 된다. **실제 학생 계정으로 운영에서 샘물 가져오기는 아직 확인하지 않았다.**
- 저장소 기본 브랜치가 `dev`라 `main`으로 가는 PR의 `Closes #n`은 이슈를 자동으로 닫지 않는다(손으로 닫음).
- 배포 뒤 피드백: 전공제도 '종류'에 심화전공이 없었다 → 이슈 #37에서 고침(0026 결과 참고).
