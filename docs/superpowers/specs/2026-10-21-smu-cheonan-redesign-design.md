# 상명대 천안캠 전용 재구성 설계 (2026-10-21)

사용자 확정 사항: 범위를 상명대 천안캠퍼스로 줄이고 완성한 뒤 확장 계획을 세운다. 화면은 상명대학교 UI(로고·전용색·캠퍼스 사진)를 바탕으로 사용자가 구상한 구성(상단 메뉴 + 사진 배너 + 흰 본문)으로 재구성하고, 회원제 + 서버 저장을 붙인다. 화면 와이어프레임은 `docs/wireframe-smu.html`(확정).

구현은 두 단계로 나눈다.

- **1단계 화면**: 천안캠 고정 + 새 화면 구성. 저장은 지금처럼 기기(localStorage)에 둔다. 로그인·마이페이지 자리를 먼저 만든다.
- **2단계 계정**: Supabase 인증·DB를 붙여 1단계의 저장 자리를 서버로 바꾼다.

## 1. 범위

- 대학은 `smu-cheonan` 하나로 고정한다. 대학 선택 UI를 없앤다.
  - `src/data.ts`의 데이터 묶음(glob)도 `data/smu-cheonan/`만 읽는다(번들에서 타 대학 제외).
  - `data/yonsei`, `data/cnu`, 엔진의 다대학 구조는 지우지 않는다(확장 때 되살림).
- 화면에서 빼는 것
  - 사이드바와 설정 창. 테마는 시스템 설정을 따른다.
  - 북마클릿 가져오기, 표 붙여넣기, 에브리타임 안내, 백업 내보내기·가져오기(상명프렌즈 JSON 포함).
  - 코드도 함께 지운다(`paste.ts`의 `bookmarklet`·`grab`, `SiteImport`의 북마클릿 분기, `fromPortal` 메시지 수신). 단 `rowsToEnrollments`·`fillCodes`는 샘물 응답 해석에 쓰므로 남긴다.
- 남기는 입력 경로: 샘물 가져오기(`api/smul.ts`), 과목 검색 추가, 직접 입력(편입 일괄·학점교류 포함).

## 2. 화면 (와이어프레임과 같음)

- **상단 메뉴**: 상명대 시그니처 로고 + "학점플래너".
  - 로그아웃 상태: 이용안내·로그인·회원가입.
  - 로그인 상태: 졸업요건·학기추천·마이페이지 · **{이름}님**(누르면 마이페이지) · 로그아웃.
  - 휴대폰 폭에서는 로고가 윗줄, 메뉴는 아랫줄 한 줄(가로 스크롤)로 둔다.
- **홈 `#/`**: 천안캠 사진 전면 배너, "상명대 천안캠퍼스 졸업요건 검사·학기 추천", [검사하기]. 로그인 상태면 [검사하기]가 졸업요건으로 간다.
- **로그인 `#/login`**: 사진 배너(제목) + 카드(학번, 비밀번호, 비밀번호 찾기 링크, [로그인 | 회원가입]).
- **회원가입 `#/join`**: ① 약관·개인정보 동의 ② 샘물 인증(학번·샘물 비밀번호) ③ 인증 결과 확인(학번·이름·학과·입학년도·가져온 과목 수) + 사이트 비밀번호 설정.
- **졸업요건 `#/result`**
  - 요약 상자: 졸업 기준·총 이수·전공·교양·일반·남은 학점 + 원형 진척률.
  - 아래에 영역 카드: 전공·전공심화·교양·기초교양·상명핵심역량교양·균형교양 등 주전공 요건 트리의 2단계 항목과 check 항목.
  - 카드의 [자세히]는 모달을 연다. 모달에는 해당 요건의 과목표(학년·학기·학수번호·과목명·이수구분·학점·이수/미이수)와 부족 설명이 들어간다.
  - 진로 트랙(SM-CDR)은 카드 하나로 묶고 자세히에서 펼친다.
  - 오류 신고 ⚑는 모달 안에 둔다.
- **학기추천 `#/plan`**: 지금 화면과 같다. 계절학기·초과 신청 스위치, 진로 트랙 선택은 이 화면에만 둔다.
- **마이페이지 `#/my`**
  - 왼쪽: 내 정보(학번·이름·학과·이수 형태·현재 학기)와 버튼 4개: 학적 수정(모달: 학과·입학년도·이수 형태·편입·유학생·휴학·현재 학기), 직접 입력 항목(모달: check 값), 비밀번호 변경, 회원 탈퇴.
  - 오른쪽: 기이수 과목 표 + [샘물에서 다시 가져오기] [과목 추가](모달: 검색/직접 입력 탭).
- **이용안내 `#/terms`**: 이용약관·개인정보처리방침 본문(수집 항목, 목적, 보관, 탈퇴 시 삭제, 샘물 비밀번호 미저장, 서울 리전 보관).
- 1단계에서는 로그인·회원가입이 아직 없다. 상단 메뉴는 로그인 상태 모양으로 두고, "회원가입" 자리의 샘물 가져오기가 기기 저장으로 동작한다.

## 3. 디자인

- **색**: 상명 전용색 SM Blue `#0E207F`(주색), SM Dark Gray `#333B3D`, SM Gold `#8D6E26`(smu.ac.kr/kor/intro/uiColor.do). 충족 초록·부족 빨강은 지금 토큰을 쓴다.
- **글꼴**: Noto Sans KR. Google Fonts를 쓰므로 CSP `style-src`·`font-src`에 fonts.googleapis.com·fonts.gstatic.com을 허용한다.
- **로고**: smu.ac.kr/kor/intro/uiSymbol.do의 시그니처(가로형, 흰 바탕용 + 남색 바탕용 JPG)를 내려받아 `public/`에 둔다. 비례·여백은 바꾸지 않는다.
- **사진**: smu.ac.kr에 공개된 천안캠퍼스 사진 1장을 고른다. 고른 사진은 쓰기 전에 사용자 확인을 받는다. 출처는 바닥글에 적는다.
- 학교 자료 사용은 사용자가 받은 학교 허가 범위 안이라는 전제다(사용자 확인 사항).
- 다크 모드는 1차에서 빼고 밝은 화면만 만든다.

## 4. 계정·저장 (2단계, Supabase)

- **프로젝트**: `credit-planner`(ref `chkmaephrtufzbktigfx`, ap-northeast-2, 2026-10-21 생성).
- **표**

| 표 | 열 | 권한(RLS) |
|---|---|---|
| `students` | `id uuid pk → auth.users on delete cascade`, `student_no text unique`, `name text`, `synced_at timestamptz` | 본인 행 select만. 쓰기는 서버 함수(service role)만 |
| `plans` | `id uuid pk → auth.users on delete cascade`, `state jsonb`(지금의 `State`), `updated_at timestamptz` | 본인 행 select·update |

- **계정 이메일**: Supabase 인증은 이메일이 필요하다. `{학번}@{가짜 도메인}`으로 만들고 메일은 보내지 않는다(관리자 API `createUser`에서 `email_confirm: true`). 가짜 도메인이 Supabase 이메일 검사를 통과하는지는 구현 때 확인한다.
- **서버 함수(Vercel, `api/`)**: 공통 샘물 모듈은 `api/smul.ts`의 `session`·`records`를 재사용하고, 학생정보 `UsrSchMng/selectStdInfo.do`를 추가한다. 학생정보에서 쓰는 필드는 `STDNO`·`NM_KOR`·`TMP_DEPT_MJR_NM`·`MJR_CD2`뿐이고, 나머지(이메일 등)는 버린다.
  - `POST /api/join` `{id, smulPw, pw}`: 샘물 인증 → 학생정보·이수과목 → 학번이 이미 가입돼 있으면 409 → `createUser` → `students`·`plans` 행 생성(학과는 이름으로 `programs`에서 찾고, 못 찾으면 비워 두어 마이페이지에서 고르게 한다. 입학년도는 학번 앞 4자리).
  - `POST /api/sync` `{smulPw}`(로그인 토큰 필요): 샘물 재인증 → 이수과목을 받아 `plans.state.es`의 샘물 출처 행만 바꾼다(직접 넣은 과목은 유지) → `synced_at` 갱신.
  - `POST /api/reset` `{id, smulPw, pw}`: 샘물 인증 성공 시 해당 계정 비밀번호 변경.
  - `POST /api/quit`(로그인 토큰 필요): `auth.admin.deleteUser`(cascade로 두 표 삭제).
- **브라우저**: `@supabase/supabase-js`로 로그인(`signInWithPassword`, 이메일은 학번으로 만듦)·로그아웃·`plans` 읽기/쓰기. 상태가 바뀌면 지금 localStorage 저장 자리에서 서버로 저장한다(입력 멈춘 뒤 1초 디바운스, 실패 시 토스트 + 재시도).
- **환경변수**: `SUPABASE_URL`, `SUPABASE_ANON_KEY`(브라우저용 `VITE_` 접두), `SUPABASE_SERVICE_ROLE_KEY`(Vercel 서버 전용, 저장소에 넣지 않음).
- **CSP**: `connect-src`에 `https://chkmaephrtufzbktigfx.supabase.co`를 추가한다.
- **샘물 비밀번호**: 요청 안에서만 쓰고 저장·기록하지 않는다(지금 `api/smul.ts`와 같음).
- **사이트 비밀번호**: Supabase 인증이 해시로 보관한다. 최소 길이 8.

## 5. 오류 처리

- 샘물 오류 문구는 지금 `api/smul.ts`의 문구를 그대로 보여 준다.
- 가입 중복 시 "이미 가입된 학번입니다. 로그인하거나 비밀번호 찾기를 이용하세요."
- 서버 저장 실패 시 화면 상태는 유지하고 토스트로 알린 뒤 다음 변경 때 다시 저장한다.
- 데이터(요건) 오류는 지금처럼 결과 화면 위 안내.

## 6. 시험

- **엔진·파서**: 지금 `npm test`를 그대로 통과해야 한다.
- **학생정보 파싱**: `src/smul.test.ts`에 가짜 `dsStdInfoList` 응답 → 허용 필드만 남는지 시험 1개를 추가한다.
- **화면**: 미리보기에서 6개 화면(홈·로그인·가입·결과·추천·마이페이지)을 PC·휴대폰 폭으로 확인한다.
- **2단계**: Supabase에서 두 계정을 만들어 다른 계정의 `plans`를 못 읽는지(RLS) SQL로 확인한다. Supabase advisors(보안) 경고 0.
- **실제 샘물 가입**: 사용자 본인 계정으로만 한다(확인 불가 항목으로 남김).
