## 🎯 과제 정의

졸업요건은 학번·학과·전공제도마다 다르고, 학생은 교육과정표와 성적표를 나란히 놓고 한 과목씩 맞춰 봅니다. 그러다 보면 빠진 요건을 졸업 직전에야 알게 됩니다. grad-planner는 이 계산을 대신해 **졸업까지 남은 것을 놓치지 않게** 하는 것을 첫 번째 목표로 합니다.

- 샘물 기록을 불러와 졸업요건을 영역별로 판정하는 **학점 계산기**
- 남은 학기마다 무엇을 들어야 졸업하는지 찾아 주는 **학점 플래너**
- 지금까지 들은 과목과 영역을 한 표로 보는 **이수 현황**
- 심화전공·다전공·부전공·마이크로전공을 미리 넣어 보는 **전공제도 계획**
- 편입생·유학생·휴학생·학번별 기준까지, 학생마다 다른 조건을 그대로

학교마다 엔진을 따로 만들지 않고 엔진 하나에 학교 데이터만 바꾸도록 설계했습니다. 샘물 비밀번호는 저장하지 않고, 성적 계산은 학생 기기 안에서 합니다.

한마디로 **졸업요건 자동 판정기 + 남은 학기 수강 계획기 + 전공제도 미리 보기**입니다.

### 학생이 겪는 문제

1. 졸업요건이 학번·학과·전공제도마다 달라, 학생이 학사안내·교육과정표를 찾아 손으로 맞춘다.
2. 다전공·부전공·마이크로전공을 신청하면 주전공 기준 학점이 바뀌는데(예: 심화전공 75 → 다전공 45 + 36), 신청 전에 미리 계산해 보기 어렵다.
3. 상명프렌즈 설문에서 가장 많은 학생이 어렵다고 답한 문제가 졸업요건 계산이다. `[확인 불가: 응답 수·비율은 사용자 자료로 채울 것]`

## 📌 공통 운영 규칙

### 결과물

- 공개 저장소와 README: 과제 정의, 실행 방법, 환경 변수 표, 폴더 지도, **AI 활용 기록**

- 이 명세서와 결정 기록(ADR)
- 테스트 결과: 엔진 V1~V10, 전공제도 테스트 MJ01~MJ14 통과 기록
- 3분 시연 영상 `[제안]`

### 원칙

- **판정 정확도 먼저:** 다른 기능과 충돌하면 졸업요건 판정이 학교 기록과 맞는 쪽을 고른다.
- **샘물 값이 정답:** 학생 기록(과목·이수구분·학점·성적)은 샘물 값을 그대로 쓴다 ([0016](decisions/0016-smul-source-of-truth.md)).
- **엔진 하나 + 학교 데이터:** 학교 규칙은 데이터에만 둔다. 코드에 학교 이름·학과·학점 숫자를 넣지 않는다 ([0001](decisions/0001-one-engine-many-data.md)).
- **화면엔 결과만:** 화면에는 결과와 이용 정보만 쓴다. 출처·판정 방식·검증 상태는 문서에만 ([0018](decisions/0018-user-facing-copy.md)).
- **최소 수집:** 샘물 비밀번호는 저장하지 않고, 허용한 열만 받는다 ([0009](decisions/0009-data-minimization.md)).
- **근거 남기기:** 모든 선택은 대안과 근거(측정·공식 문서·선행 사례·사용자 결정)를 ADR로 남긴다. 근거가 약하면 약하다고 쓴다.
- **과설계 금지:** 요청하지 않은 추상화·라이브러리를 넣지 않는다.

### 개발 규칙 (AI 활용 포함) `[결정 2026-11-08]`

1. **브랜치:** `main`(배포) · `dev`(기본) · 작업 브랜치 `feature/` `fix/` `refactor/` `docs/` `chore/` + 파트 번호 + 짧은 이름 (예: `feature/P2-engine-core`). 작업 브랜치는 `dev`에서 따고 `dev`로 PR을 보낸다. `main`은 `dev → main` PR로만 바꾼다.
2. **보호:** `main`·`dev` 모두 PR 없이 바꿀 수 없다(관리자 포함). 강제 푸시·삭제 금지. CI가 생기면 통과를 병합 조건에 더한다.
3. **커밋:** 한 커밋 한 변경. 제목은 `유형: 무엇을 바꿨는지` 한 줄. 본문은 필요할 때만 빈 줄 뒤 목록 2~4줄. 사람이 한눈에 알아보게 쓴다.
4. **PR:** 본문은 `무엇을 / 왜 / 확인 방법`. 커밋 이력을 남기려고 merge commit으로 합친다.
5. **AI 사용:** Claude Code가 브랜치·커밋·푸시·PR·병합까지 대신 한다. 커밋 작성자는 사용자 한 명이고 `Co-Authored-By` 등 AI 표기는 넣지 않는다. AI 도움은 README 'AI 활용 기록'에 모아 적는다.
6. **설명 책임:** 저장소의 어떤 파일·함수든 무엇을, 왜 그렇게 했는지 설명할 수 있어야 한다. 그래서 결정은 ADR, 모듈은 파일 머리 주석에 이유를 남긴다.
7. **테스트 보호:** 테스트를 고쳐서 통과시키지 않는다. 오라클 정답 파일(`oracle/expected.sha256`)은 데이터가 바뀔 때만 다시 만든다.
8. **의존성:** 새 라이브러리는 PR에 이유와 라이선스를 적고 사용자 승인 뒤 넣는다.
9. **비밀값과 자료:** 키·토큰은 환경 변수에만. 실제 학생 정보는 저장소·테스트·AI 대화에 넣지 않는다(테스트는 가짜 학생).

## 🗂 프로젝트 명세 — 무엇을 만드나

### 기술 스택 `[결정 2026-11-08]`

첫 버전은 claude.ai 아티팩트(HTML 한 파일)로 시작해 그 흐름대로 웹으로 옮겼고, **왜 웹인지는 기록하지 않았다.** 이번에는 학생 문제에서 기준을 세우고 대안을 비교해 정했다. 자세한 비교는 [0021](decisions/0021-stack-review.md).

| 층 | 결정 | 이유 |
|---|---|---|
| 학생이 쓰는 형태 | **웹 + PWA**, 이식이 끝나면 같은 빌드를 **Capacitor로 iOS·Android 앱 포장** | 설치 없이 링크로 열림. 앱스토어 노출·앱 알림은 포장으로 더함 |
| 계산 위치 | **학생 기기 안** (HiGHS WebAssembly, Web Worker) | 성적이 서버로 가지 않음 |
| 화면 프레임워크 | **React + Vite** | 그대로 이식 가능 |
| 서버·DB | **Vercel(서울 함수) + Supabase(서울)** | 무료. 상용화하면 Vercel은 유료 전환 필요 |

**판단 기준**

1. 학생은 학기에 몇 번(수강신청 전, 전공제도 신청 기간인 5월·11월) 확인한다 → 설치 없이 바로 열려야 한다.
2. 휴대폰과 PC 모두 쓴다 `[확인 불가: 설문 자료로 비율 확인]`.
3. 성적은 민감 정보다 → 계산은 학생 기기 안에서, 서버로 성적을 보내지 않는다.
4. 서버가 꼭 필요한 일은 둘이다: 샘물 중계 로그인(한국 리전), 회원 저장.
5. 1인 개발 → 구성 요소가 적고, 하나하나 설명할 수 있어야 한다.

**검토한 대안** (형태별. 화면·서버 층의 대안은 0021)

| 안 | 구성 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A. 웹 + PWA** (채택) | Vite·React·TypeScript, 계산은 브라우저(HiGHS WebAssembly·Web Worker), Vercel 함수(서울)·Supabase. 여기에 홈 화면 설치(PWA) 추가 | 링크로 바로 열림. 엔진 한 벌을 브라우저·테스트·서버가 같이 씀. 이식 비용 최소 | 앱스토어 노출 없음. iOS 알림은 홈 화면에 추가한 경우만(iOS 16.4+) |
| B. Next.js 풀스택 | 서버 렌더링·라우팅·API를 한 프레임워크로 | 라우팅·검색 노출 내장 | 계산은 어차피 브라우저라 서버 렌더링 이득이 작다. 화면 전부 다시 작성 |
| **A+. 앱 포장** (채택, 이식 후) | A의 빌드를 Capacitor로 iOS·Android 앱에 넣음 | 스토어 노출, 앱 알림. 엔진 그대로(시스템 웹뷰) | Apple이 웹사이트 재포장 수준 앱은 반려(지침 4.2) → 알림·오프라인 보기 필요. iOS 빌드는 Mac 필요 → GitHub Actions macOS 러너 |
| C. 모바일 앱 | React Native(Expo) + 별도 웹 | 앱 알림·스토어 | 스토어 심사·Apple 개발자 등록비. HiGHS WebAssembly가 React Native 기본 엔진(Hermes)에서 도는지 공식 확인 불가 → 추천을 서버로 옮겨야 할 수 있음 |
| D. 서버 계산 | Python(FastAPI) 등 + DB | Python 최적화 생태계 | 성적이 서버로 감(원칙 '최소 수집'과 충돌). 엔진·테스트 전부 재작성, 서버 운영비 |

**벤치마킹:** 다른 대학 학생들이 만든 졸업요건 서비스(명지대·동국대·GIST·수원대 등)는 모두 웹이고, 광운대는 크롬 확장이다(2026-10-21 조사).

**결정: A, 이식 후 A+.** 학생 문제(가끔, 설치 없이, 성적은 기기 안에서)와 맞고 엔진·테스트를 그대로 옮길 수 있다. 앱 포장은 같은 빌드를 쓰므로 웹을 버리지 않고 더한다.

### 전공제도 명세 (천안캠퍼스) `[결정 2026-11-08: 학교 명세대로 재정의]`

> 기존에는 다전공을 '여러 전공을 듣는 것' 하나로만 다뤘다. 학교 명세에는 전공제도가 8종이고, 심화전공(단일전공을 개선한 제도)과 연계·융합·자기설계 전공이 빠져 있었다. 아래가 새 정의이고, 엔진 반영은 P5에서 한다.
> 출처: 상명대 학사안내 전공제도 7개 페이지(2026-11-08 확인), 천안 입학자 졸업이수학점 공지, 2026-2 이수구분 정정 안내. 링크는 문서 끝 '참고'.

**공통 규칙**

- 천안캠퍼스 **2018학번 이후**는 졸업하려면 **다전공·부전공·심화전공 중 하나**를 이수해야 한다. 마이크로전공 2개 이상 이수도 이 항목을 채운다.
- **이수 의무 제외:** 편입학자, 공학인증대상자, 체육특기자, 특수교육대상자, 외국인특별전형, 계약학과, 특성화고 등을 졸업한 재직자 전형 입학자.
- 신청·취소는 매 학기 **5월·11월**(학사공지). 모집 인원 제한 없음(부전공은 학과별 선발).
- 신청 전에 들은 과목도 인정받을 수 있다. 반영하려면 **이수구분 정정**(학과·교무처 승인)이 필요하다.

| **심화전공** | 제1전공의 심화 교육과정을 이수. 단일전공을 개선한 제도(천안 2018학번부터). 학위 하나 | 2학년 2학기 재학생 중 다전공·부전공을 신청하지 않은 학생. **3학년 1학기 진입 때 자동 전환**(매년 7월·1월) | 주전공 학점 안에 학과 지정 전공심화 교과목 **15학점 이상** 포함 | 전공심화 과목은 전공학점으로 인정. 심화전공을 포기하면 다전공·부전공을 반드시 이수 |
| **다전공 — 제2전공** | 다른 학부(과)의 졸업학점을 이수해 **학위 각각** 인정 | 재학생. 제3전공까지 지원 가능. 추가전형 학과는 최저기준 통과, 사범계는 교직과정 이수자만 | 주전공 45 + 제2전공 36 (2023~2026학번) | 같은 학수번호는 **최대 6학점 양쪽 인정**. 다전공 학과의 입학학년도(또는 복학 원학년) 교육과정. 제2전공 미충족이면 학위 불가(취소하면 제1전공 학위 가능). 취소하며 부전공 전환 가능 |
| **다전공 — 연계전공** | 관련 있는 2개 이상 학부(과)가 연계해 설계한 교육과정. 학위 각각 | 재학생. 천안 3개: 글로벌문화콘텐츠, 스토리텔링, AI영상디자인 | 영역별 **36학점 이상** | 6학점 중복 인정. 교육과정표는 연도별(2024~2026 공개). 미충족이면 학위 불가 |
| **다전공 — 융합전공** | 학과 장벽을 넘는 융합 교육과정. 학위 각각 | 재학생. 천안 6개: 스마트리빙디자인, 글로벌마케팅, 글로벌데이터경영, 미래모빌리티융합시스템, 디스플레이-반도체소부장, 에너지융합 | 영역별 **36학점 이상** | 연계전공과 같음. 연도마다 개설 전공이 바뀐다(2024년 목록과 다름) |
| **다전공 — 자기설계융합전공(SM-ISM)** | 학생이 2개 이상 전공을 융합해 직접 설계, 위원회 심의·총장 승인 | 재학생. 지도교수와 협의해 샘물로 신청 | 심화전공으로: SM-ISM **75학점 이상**(전공심화 15 포함). 다전공으로: 제1전공 **45** + SM-ISM **36** | 위원회 지정 필수과목 이수. 6학점 중복 인정. 교류협정대학 과목 편성 가능. 과목 목록이 학생마다 다르다 |
| **부전공** | 제1전공 외 다른 학부(과) 21학점 이상 → **이수경력** 인정(학위 아님) | 재학생. 학과별 선발. 교직목적 부전공 없음 | 제1전공 **60** + 부전공 **21** | 승인 전 들은 과목은 일반선택 → 승인 후 이수구분 정정해야 부전공 학점. 다전공 취소자는 부전공으로 전환 가능 |
| **마이크로전공** | 세부·학제 간 교육과정(9~15학점)을 낮은 요건으로 이수. 유형: 자기전공활용형·융합연계형·사회수요맞춤형 | 제한 없음. 다른 캠퍼스 것도 신청 가능 | 그 교육과정의 **모든 과목**. 이수구분 `MD`(미신청자가 들으면 `일선`) | 다른 전공제도와 **중복 인정 불가**. 교양 과목은 MD로 정정해야 하고 교양과 중복 불가. 학점교류·K-MOOC·대체과목 불가. 취소하면 일반선택 |
| **전공선택** | 둘 이상 전공을 가진 학부·자유전공 입학생이 **주전공을 정하는 절차** (위 이수 의무와 별개) | 1학년 1학기부터 신청, **3학년 2학기 재학 중에는 반드시** 선택 | — | 샘물로 신청(서류 없음). 확정 뒤에만 전과 신청 가능 |

**마이크로전공 2개로 전공제도를 채울 때 주전공 학점**

| 대상 | 주전공 | 비고 |
|---|---|---|
| 천안 2023학번 이후 (간호학과 제외) | 60 + 마이크로전공 2개 | |
| 천안 2022학번 이전 (공과대학·간호학과 제외) | 60 + 2개 | |
| 천안 2022학번 이전 공과대학 | 74 + 2개 | 경영공학과는 공과대학이지만 60 |
| 천안 간호학과 | 94 + 2개 | |

이때 전공심화는 '해당없음'이다. 마이크로전공을 신청만 하고 2개를 다 이수하지 못하면 다른 제도(다전공·부전공·심화전공)로 채워야 학위를 받는다.

**이수구분 정정 코드** (성적표·샘물에 나타나는 값): 다전공 `2학기`·`2전선`, 연계 `연필`·`연선`·`2연필`·`2연선`, 융합 `융필`·`융선`·`2융필`·`2융선`, 부전공 `1부심`·`1부선`·`2부심`·`2부선`, 마이크로 `MD`·`1MD`·`2MD`·`3MD`. 전공심화로는 정정할 수 없다.

**엔진 반영 방향** (P5에서 ADR로 확정)

- 이수 형태 이름을 학교 용어로 바꾼다: `single`(단일전공) → **심화전공**. 학생 화면에서 '복수전공'이라는 말은 쓰지 않는다(학교 용어는 다전공).
- 다전공을 한 종류로 두지 않고 **제2전공·연계·융합·자기설계** 네 갈래로 나눈다. 제3전공까지 여러 개를 둘 수 있게 한다.
- **6학점 중복 인정**(제1전공과 다전공의 같은 학수번호)과 **마이크로전공 중복 불가**를 판정에 넣는다.
- **이수 의무 제외 대상**(편입 등)은 전공제도 항목을 '해당없음'으로 판정한다.
- **심화전공 자동 전환:** 3학년 1학기 이후인데 다른 제도가 없으면 심화전공으로 본다.
- 연계·융합전공 과목은 천안 교육과정표 PDF(2024~2026)에서 데이터로 만든다. 자기설계융합전공은 학생이 승인받은 이수계획표의 과목을 직접 넣는다.
- `[확인 불가]` 2022학번의 다전공·부전공 시 주전공 학점, 연계·융합전공의 '영역별' 최소 학점, 마이크로전공 학점이 졸업 총학점에 드는지.

### 업무 규칙 (졸업요건 판정)

| 규칙 | 내용 |
|---|---|
| 기록 우선 | 과목·이수구분·학점·성적은 샘물 값. 이수구분이 있으면 카탈로그보다 우선 |

| 평점 | 4.5 만점 환산표로 계산, 직접 입력보다 우선 ([0014](decisions/0014-gpa-auto.md)) |

| 계획 | 추천은 남은 학기의 학기 상한·최소 학점 안에서, 요건 부족분 → 학기 최소 부족분 → 추천 학점 → 취향 순으로 최적 |
| 전공제도 | 위 '전공제도 명세' |

### 3. 사용성 `[제안]`

천안캠퍼스 학생 3명 이상이 '샘물 가져오기 → 남은 학점 확인 → 다전공 넣어 보기'를 혼자 해 보고, 성공 여부와 걸린 시간을 남긴다.

## 📝 완성 기준

| 수준 | 기준 |
|---|---|
| S | 필수 전체 + 권장 3개 이상 + 엔진 회귀·MJ 테스트 100% + 사용성 테스트 + 설명 질의 통과 |
| A | 필수 전체 + 권장 2개 이상 + 엔진 회귀·MJ 테스트 100% |
| B | 필수 전체 배포 |
| C | 엔진 이식(P2~P4)만 완료 |

**통합 시연 시나리오 (3분)**

1. 샘물 학번·비밀번호로 가져오기 → 확인 화면에서 학과·과목 확인 → 저장
2. 학점 계산기: 졸업까지 남은 학점과 영역별 부족분
3. 학점 플래너: 남은 학기 추천, 과목 하나 바꾸기
4. 전공제도 계획: 심화전공 → 제2전공으로 바꾸면 주전공 75 → 45 + 36, 같은 과목 6학점 중복 인정
5. 마이크로전공 2개로 바꾸면 주전공 60, 전공심화 해당없음
6. 편입생 프로필: 전공제도 '해당없음'
7. 휴대폰 화면으로 같은 흐름

## ✅ 해야 할 일

### README 'AI 활용 기록'에 쓸 것

쓴 도구, 잘된 사례 3개, AI가 틀려서 사람이 고친 사례 3개. 후보:

- 잘된 사례: 추천을 탐욕 보정 대신 정수계획으로 다시 분류해 회귀 0건 ([0003](decisions/0003-ilp-recommendation.md)), 기존 앱을 오라클로 두고 차이를 자동 측정 ([0004](decisions/0004-oracle-verification.md)), 표준(OWASP·NIST)과 실제 구현을 비교해 남용 방어 설계 ([0013](decisions/0013-smul-failure-handling.md))
- 사람이 고친 사례: 다전공을 '여러 전공 듣기' 하나로만 다룸 → 학교 명세 8종으로 재정의(이 문서), 마이크로전공 신청만으로 이수 형태를 바꿔 전공심화가 빠짐 → 2개 '이수' 기준으로 정정 ([0017](decisions/0017-what-if-mode-category.md)), 탐욕 규칙을 계속 덧대다 회귀가 4건에서 9건으로 늘어남 → 문제 분류부터 다시 ([0003](decisions/0003-ilp-recommendation.md))

### 미결 사항 (사용자 결정 필요)

1. 앱 스토어 등록 여부와 시점(Apple·Google 개발자 계정 필요)
2. 상명프렌즈 설문 수치(응답 수, 졸업요건 계산을 어렵다고 답한 비율)
3. 개인 과제 제출 마감일 → 파트별 일정
4. 저장소 라이선스(정하지 않으면 공개여도 재사용 불가)
5. 연계·융합전공 데이터 범위: 2026학년도만, 또는 2024~2025 개설 전공까지
