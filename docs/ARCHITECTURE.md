# 학점플래너 일반화 설계·검증 기록

> 첫 버전 저장소(`grad-planner`, 비공개)의 기록을 그대로 옮겼다. 파일 경로는 이식하며 바뀔 수 있고, 이식 계획은 [`SPEC.md`](SPEC.md)에 있다.

작성 2026-10-20. 대상: 상명프렌즈 학점플래너(claude.ai 아티팩트 V44)를 여러 대학 상용 서비스로 옮기기 위한 설계와 그 검증.
결정별 근거·검토한 대안·벤치마킹은 [`docs/decisions/`](decisions/README.md)에 따로 모았다.

## 0. 결론

- **현재 앱은 프로토타입으로는 성공했지만 확장 기반으로는 맞지 않는다.** 알고리즘 아이디어·데이터 형식·수집 로직은 살리고, 빌드·런타임·규칙 표현·배포는 새로 짰다.
- **대학·학번·학생 유형은 엔진 하나와 데이터로 일반화된다.** 학교별 엔진은 만들지 않는다. 학교마다 다른 것은 제약의 데이터이지 문제의 종류가 아니다.
- **추천은 정수계획(HiGHS)으로 정확히 푼다.** 탐욕 알고리즘은 시간 초과·풀이기 실패 때 쓰는 대체용으로만 남긴다. 3,700개 사례에서 정수계획 해는 현재 앱과 탐욕보다 나쁜 경우가 한 번도 없었고, 현재 앱은 34.5%의 사례에서 최적보다 덜 채웠다.
- **확장의 병목은 엔진이 아니라 데이터다.** 대학×프로그램×입학년도마다 공개 문서를 찾고 표의 의미를 확정하는 일이 비용의 대부분이다(외부 대학 1개 학과 약 45~50분, 사람 검토 전).

## 2. 목표 아키텍처

```
etl/<univ>/raw(원본 옮긴 TSV·PDF 텍스트) ──▶ etl 변환 ──▶ data/<univ>/gen/*.json  (교육과정: 연도별 전체 스냅숏)
                                                     data/<univ>/rules.json + sets.csv (요건: 사람이 관리, 연도 범위)
                                                     data/<univ>/golden/*.json (문서만 보고 손으로 계산한 기대값)
                                                             │ 정적 파일, 프로그램 단위로 불러옴
engine/ (순수 TypeScript, DOM 없음) ◀───────────────────────────┘
   audit.ts   평가기: 수강 기록 → 판 고르기 → 태그 → 재수강·중복 → 규칙 트리 판정   ← 기준은 여기 한 곳
   plan.ts    추천: 정수계획(HiGHS) → 실패 시 탐욕 대체 → 평가기로 다시 판정
   check.ts   데이터 참조 무결성 검사
src/ (React+Vite 웹앱 MVP, 성적은 기기 localStorage, §10) ──▶ 정적 호스팅 ──▶ (후속) Capacitor 모바일
```

- **엔진은 의존성이 HiGHS 하나**다(`highs@1.15.3`, MIT, 하위 의존성 없음, WASM 3.5MB). Node 24가 TS를 바로 실행하므로 엔진에는 빌드 도구가 없다.
- **백엔드는 아직 없다.** 데이터는 정적 JSON이고, 성적은 기기에만 둔다. 기기 간 동기화·유료 계정·동의 기반 수집 중 하나가 생기면 붙인다.
- **UI는 React + Vite + TS(예정).** 전체 다시 그리기·전역 상태 문제를 선언형 렌더러로 없앤다. React 런타임(gzip 약 45KB)은 OCR 모델 29MB에 비해 작다. 모바일은 같은 빌드를 Capacitor로 감싼다.
- **브라우저에서는 풀이를 Web Worker에서 돌린다**(HiGHS 문서 권고). `highs.wasm` 위치는 `locateFile`로 넘긴다.

## 3. 요건 IR (`engine/types.ts`)

**버전 축은 둘이다.**
- 요건은 학생의 `catalogYear`(입학년도)로 고른다.
- 과목의 학점·이수구분은 수강한 학기의 판(`policy.edition`)에서 읽는다. 현재 앱의 `o:`/`n:` 카드를 일반화한 것이다.
- 성적표에 적힌 이수구분·학점이 있으면 카탈로그보다 우선한다.

**규칙은 5종이다.**

| 규칙 | 뜻 | 예 |
|---|---|---|
| `credits` (+`capped`) | 조건에 맞는 과목 학점 합 ≥ 기준. 상한을 넘는 학점은 뺌 | 전공 75학점, 편입 인정학점 상한 |
| `courses` | 조건에 맞는 과목 수 ≥ 기준 | 캡스톤, 공학수학(1)(2) |
| `all{need}` | 하위 규칙 전부 또는 n개 이상 | 균형교양 5개 영역 중 3개 |
| `check` | 학생이 입력하는 값 ≥ 기준 | 평점, TOPIK, 포트폴리오 인증 |
| `use` | 공유 블록 + 숫자 변수 | 학과·연도마다 숫자만 다른 요건 |

- 과목 조건(`Filter`)은 학수번호·과목명(둘 중 하나) + 태그 조건(`tags` 하나 이상, `every` 모두, `not`)이다.
- 태그는 대응표에서 계산한다: 이수구분 → 태그, 교양 영역 → 태그, 출처(편입·학점교류) → 태그, **학수번호 모양 → 태그(`codeTags`, V2에서 추가)**.
- 요건 세트(`ReqSet`)는 프로그램 × 입학년도 범위 × 조건(역할·이수 형태·편입·유학생)으로 고르고, 근거 문서(`src`)가 반드시 있다.
- **데이터가 없는 학번·유형은 조용히 다른 기준을 쓰지 않는다.** 결과는 `ok:null`(확인 필요)이다.

**사례별 표현**

| 사례 | 표현 |
|---|---|
| 재학생·휴학·복학 | `Profile.leaves`, 첫 학기 `startTerm`. 학년·학기 순번은 휴학을 건너뛰어 계산 |
| 편입생 | `admission:'transfer'`, `startSemester:5`. 인정학점은 과목 내역 없는 일괄 블록(`lump`, `src:'transfer'`) + `capped` 상한. 요건 차이는 편입 조건 세트 |
| 계절학기 | 학기 `YYYY-S`/`YYYY-W`. 판정은 항상 포함, 추천은 학생이 켤 때만(`opts.season`). 한도·대상은 `policy.season` |
| 유학생 | `student:'international'` 세트(예: TOPIK `check`), 유학생 전용 과목 `policy.intlOnly` |
| 다전공·부전공 | 역할 `second`/`minor`, 주전공 기준은 `with` 조건으로 고름 |
| 진로 트랙(SM-CDR 등) | 역할 `track` 프로그램 하나 |

**아직 넣지 않은 것**: 선수과목, 평점 척도 계산, 다전공 중복 인정 한도, 변형 조합(유학생이면서 편입생은 지금은 조합 세트를 따로 써야 함). 첫 데이터가 요구할 때 규칙 종류나 조건을 추가한다.

## 4. 추천 엔진

### 4-1. 결정 경위
1. 처음에는 현재 앱의 탐욕 알고리즘을 옮기고 검산·1과목 수리를 붙였다.
2. 탐욕 규칙을 고칠수록 다른 사례가 깨졌다(예: 계절학기 우선 규칙 → 현재 앱 대비 회귀 4건 → 9건). 측정 기준(하한)도 필요조건일 뿐이라 불가능한 사례를 엔진 실패로 셌다.
3. 문제를 분류했다. **학기별 학점 상한(배낭) + 여러 요건 동시 충족(집합 덮기)** 으로, 탐욕으로는 해의 존재조차 보장되지 않는 종류다. 요건 규칙 5종은 모두 선형 제약으로 바뀐다. 실제 크기(후보 약 300 × 학기 ≤ 15)는 정수계획으로 감당된다.
4. 그래서 **요건 충족·최소 부족분은 정확히 풀고, 취향은 같은 모델의 하위 목적**으로 두었다. 비슷한 단계식 구조의 선행 사례: GradPlanner(INFORMS 2026).

### 4-2. 모델
- **변수**: 후보 묶음 k를 학기 t에 듣는 과목 수 `n[k,t]`(묶음 크기가 1이면 0/1).
  - **대칭 제거**: 학점·채우는 칸·계절 가능·전공 여부·개설 학기·관심 트랙·권장 학기가 같은 후보는 구별되지 않으므로 묶는다. 해 공간은 같고 변수가 크게 준다.
- **제약**: 묶음별 과목 수 상한, 학기별 학점 상한(이미 넣은 과목 빼고), 학기 최소학점(부족분 변수가 있는 약한 제약), 요건 칸마다 `기존 + Σ 계수·n + 부족분 ≥ 남은 양`, 고르기 묶음은 하위 칸마다 충족 여부 변수와 `Σ y + 부족분 ≥ 남은 개수`.
- **목적(사전식 우선순위)**: ① 요건 부족분 × 1000 × 단위(학점 1, 과목·영역 3) × (1 + 가중치/10) ② 학기 최소학점 부족분 × 10 ③ 추천 학점 × 1 ④ 취향(계절 0.0005, 권장 학기 거리 0.0001, 관심 트랙 −0.0002).
- **허용 간격 0.5**: ①~③의 차이는 정수라 더 나은 해는 목적값이 최소 1 − 0.06(취향 합 상한)만큼 작다. 그래서 0.5 간격에서 멈춰도 ①~③은 정확히 최적이고, 취향(동점 처리)만 최선 노력이다.
- **검산**: 풀이 결과는 평가기로 다시 판정한다. V3에서 풀이기가 본 칸별 부족분과 평가기 판정이 3,700건 모두 같았다(변환 버그 없음).
- **대체**: 풀이기를 못 불러오거나 시간 제한(기본 1초) 안에 해가 없으면 탐욕 + 1과목 수리.

## 5. 데이터·연도·대학 확장

- **교육과정(생성 데이터)은 연도별 전체 스냅숏**이다. 학교 원본과 1:1로 맞춰 볼 수 있고, 과거 연도 추가도 새 연도 추가와 같은 작업이다(델타는 쓰지 않음).
- **요건·대체표·정책(수기 데이터)은 연도 범위**다. 요건이 그대로면 사람이 확인한 뒤 `to`만 늘린다. 그 수정이 곧 확인 기록이다.
- **새 판 추가**는 `etl/compose.ts addEdition`이 옛 판 대응표를 새 판 기준으로 합성한다(엔진은 한 단계 대응만 본다).
- **대학별 어댑터 계약**: `etl/<univ>/raw/`(원본 옮김, 출처·수집일) → 변환(`etl/tsv2catalog.ts` 등, 결정적) → `data/<univ>/{gen,rules.json,sets.csv,sources.json,golden}`. `engine/check.ts`와 골든 테스트를 통과해야 배포한다.
- **연간 작업(매년 3월 1일, 사용자 결정 2026-10-27)**: 그 해 입학 학번의 졸업 기준(졸업이수학점표·교육과정·교양 영역 기준·SM-CDR 기준)을 넣는다. 순서: 새 학년도 수집 → 변환 → 판 차이 검토 → 대응표 확정 → 요건 범위 연장(`sets.csv` `to`) 또는 새 세트 → `npm test` → 배포. 학생 기록은 샘물에서 오므로 갱신 대상은 졸업 기준뿐이다. 주의: `etl/smu-cheonan/migrate.ts`는 V44 사본(2022~2026학번)에서 한 번 옮기는 도구라, 2027학번부터는 학교 원본 표를 `etl/smu-cheonan/raw/`에 두고 읽는 변환이 필요하다(아직 없음).
- **대학 선정**: 공개 수준(A: 로그인 없는 HTML, B: 공개 PDF, C: 로그인 전용) × 학생 수 × 학교 포털 자가진단 품질의 역수. 조사표는 `data/_survey.csv`, 요약은 `data/_survey_summary.md`.
- **과거 학번**: 군휴학 때문에 2020~2021학번 상당수가 지금 3~4학년이다. 과거 확장을 초기 커버리지로 다루기를 권한다.

## 6. 학교 계정 연동(시간표·성적 바로 불러오기)

- **원칙(2026-10-21 바꿈): 학교 비밀번호는 저장하지 않는다.** 학교가 허가한 곳(상명 샘물)은 학생이 넣은 학번·비밀번호로 서버가 대신 로그인한다(§6-5). 그 밖의 학교는 학생이 학교의 실제 로그인 화면에서 직접 로그인하고, 로그인된 화면의 표를 기기 안에서 읽는다.
- **경로**: 모바일은 앱 안 브라우저에서 포털을 열고 추출 스크립트를 실행한다. 웹(PC)은 북마클릿이나 확장 프로그램을 쓴다. 공통 대체 경로로 표 붙여넣기·PDF·OCR이 있다.
- **추출기**: 대학마다 `portal/<univ>/{pages.json, extract.ts, fixtures/*.html}`. 포털이 개편되면 깨지므로 fixture로 테스트하고, 실패하면 붙여넣기로 안내한다.
- **서버 대리 로그인**: 학교 허가가 있는 곳만 쓴다(상명 샘물, §6-5). 비밀번호는 요청 안에서만 쓰고 저장하지 않는다. 2단계 인증·차단 위험은 남는다.
- **한계**: 불러오는 것은 학생 본인 시간표다. 시간표가 겹치지 않는 추천에는 개설 강좌 시간표(수강편람)라는 별도 데이터가 필요하다.

### 6-1. 웹앱 구현(2026-10-20): 학교 사이트에서 가져오기

```
학점플래너 탭 ──window.open(포털, noopener 없음)──▶ 포털 탭: 학생이 학교 로그인 화면에서 직접 로그인
      ▲                                              성적 조회·학기별 시간표 화면에서 북마클릿 클릭(샘물은 아무 화면)
      │ postMessage({type:'grad-planner/rows', rows}, 학점플래너 출처)   ◀── 화면의 표(같은 출처 프레임 포함)를 읽음. 샘물은 학생 세션으로 성적·수강을 요청(§6-3)
      └── ack ──▶ (ack가 1.5초 안에 없으면 표를 클립보드에 복사 → '붙여넣기'로 넣음)
받은 표 → src/paste.ts rowsToEnrollments(표마다 머리글 다시 읽기, 표 앞 제목의 학기) → 미리보기 → 학생이 확인한 뒤 추가
```

- **받는 쪽 검사**: 앱이 연 포털 창(`e.source === 연 창`)에서 온 메시지만 받는다. 셀 수·길이를 자르고, 자동으로 넣지 않고 미리보기에서 학생이 누를 때만 추가한다. 보내는 쪽은 받는 출처를 북마클릿에 고정한다. 학생이 1단계 개인정보 수집·이용 동의를 체크해야 포털 열기 버튼이 켜지고(동의 시각은 기기에만 저장), 체크를 풀면 앱이 연 창을 잊어 그 뒤 메시지를 받지 않는다.
- **읽지 않는 것**: 비밀번호·쿠키·저장소. 북마클릿은 화면의 표 중 과목 머리글(학수번호·교과목명, `paste.ts`의 `isHeader`와 같은 기준)이 있는 표만 보낸다. 학적·인적 사항 표는 학교 탭 밖으로 나가지 않는다.
- **포털 주소**: `rules.json`의 `portal`(`{ name, url, hint }`). 상명 `https://smul.smu.ac.kr/`(통합정보시스템, 접속 확인), 연세 `https://portal.yonsei.ac.kr/`, 충남 `https://portal.cnu.ac.kr/`(접속만 확인, 성적 화면 위치 미확인).
- **시험**: 모의 포털(다른 출처)로 Playwright에서 전체 경로(창 열기 → 북마클릿 → 수신·ack → 미리보기 → 추가)와 앱이 열지 않은 창의 메시지 무시를 확인했다. 샘물은 §6-3에서 실제 로그인 화면으로 확인했다: 표가 `<table>`이 아니라서 표 읽기 대신 요청 방식으로 바꿨다. 실제 샘물에서 앱 창까지 보내는 마지막 단계는 사용자가 본인 브라우저에서 확인하기로 했다(내장 브라우저는 새 창을 같은 탭에서 열어 시험할 수 없었다).
- **시간표**: 학기 칸이 없는 표(샘물 학기별 시간표 등)는 미리보기에서 학기를 고른다(기본 현재 학기).
- **에브리타임**: 보류(§6-2). 연동은 요구사항으로 유지하고, 운영사(비누랩스)의 이용 허락을 받으면 같은 직접 로그인 구조로 재개한다. 그때까지 북마클릿은 `everytime.kr`에서 안내만 띄우고 멈추며, 앱의 '에브리타임 열기'는 뺐다. 학수번호 없는 행을 과목명으로 찾는 `fillCodes`는 학교 시간표 표에 그대로 쓴다.
- **모바일**: 앱 안 브라우저(Capacitor InAppBrowser)에 같은 추출 코드를 주입한다(모바일 단계).

### 6-2. 연동 방침 점검(2026-10-20)

방침: 학생이 각 서비스의 로그인 화면에서 직접 로그인하고, 학점 계산에 필요한 과목·학점·성적·이수구분·학기만 가져온다. 자동 접근이 서비스 정책에 어긋나면 제한을 밝히고 직접 입력·붙여넣기로 대신한다. 확인은 로그인 전 공개 화면·약관·응답 헤더로 했다.

| | 샘물(상명대 통합정보) | 에브리타임 |

### 6-3. 샘물 로그인 후 구조(2026-10-20, 학생이 앱 안 브라우저에서 직접 로그인한 세션에서 확인)

- **요청 형식(실제 요청으로 확인)**: `POST`, `application/x-www-form-urlencoded`. 본문은 eXbuilder 방식으로 DataMap 필드를 `@d1#<필드>`로 보내고 `@d#=@d1#`·`@d1#=<DataMap id>`·`@d1#tp=dm`을 붙인다. **`_AUTH_MENU_KEY`(해당 메뉴의 `MENU_ID`)가 없으면 HTTP 200에 `ERRMSGINFO` `CMN003.CMN@CMN038` "메뉴에 대한 접근권한이 없습니다"가 온다.** 메뉴 키만 맞으면 그 화면을 열지 않아도 응답한다(수강신청현황표로 확인). 요청 값은 메인 화면의 `dmUserInfo`(`USER_ID`·`STUD_NO`·`USER_NM`·`ORG_CLS_RCD`·`CAMPUS_RCD`)로 채운다. 화면이 함께 부르는 학생 검색(`/UsrStudSrh/list.do`)은 생년월일·계좌·연락처까지 돌려주므로 부르지 않는다. 오류 문구의 줄바꿈은 줄바꿈 문자가 아니라 역슬래시와 n 두 글자로 온다.
- **한 번에 가져오기(구현, `src/paste.ts` `grab`)**: 학점플래너에서 동의 체크 → '샘물 열기' → 학생이 직접 로그인 → 샘물 통합정보시스템(smul.smu.ac.kr) 아무 화면에서 북마크(로그인 뒤 샘물 포털 portal.smu.ac.kr로 가는 경우가 있어, 다른 smu.ac.kr 화면에서 누르면 통합정보시스템으로 옮겨 간 뒤 한 번 더 누르게 한다. 사용자 시험에서 확인 창이 안 뜬 원인으로 추정, 2026-10-20) → "시간표와 성적 정보를 가져오시겠습니까?" 확인 → 학생 세션으로 ①②와 수강신청현황을 차례로 요청(학기 수 + 3번) → 학수번호·교과목명·이수구분·학점·성적·학기만 남겨(이번 학기 수강 중은 성적에 이미 있으면 뺌) 학점플래너 창으로 보낸다. 실제 학생 세션에서 성적 5개 학기 35과목 + 이번 학기 수강 중 7과목, 열 5개, 학점 빈 칸 0, 학기 해석 전부 성공, 이름·학번·연락처 0건을 확인했다(값은 기록하지 않음). 샘물 이수구분(교선·1전선·1전심·일선·교필)은 상명 `rules.json`의 `categories`에 모두 있다.
- **학점포기·재수강**: 학점포기 표시(`REC_GVUP_NM`)가 있는 과목은 보내지 않는다(학점포기 신청 화면 안내: 확정하면 '포기후 이수구분별 취득학점'으로 성적에 반영). 이 학생은 35과목 모두 빈 값이라 포기했을 때 실제로 어떤 값이 오는지는 확인하지 못했다. 재수강은 보낸 뒤 엔진이 처리한다(같은 과목은 최근 학기만, F·NP는 0학점). 이 학생 데이터에서 재수강 표시(`재수강`)는 이전에 F를 받은 기록에 붙어 있었고, 엔진 규칙으로 계산한 취득학점 합계가 샘물 총 취득학점(`dmStdInfo.strTotGetCdt`)과 같았다(차이 0, 학기별 `GET_CDT` 합과도 같음). 성적 종류는 등급 32·P 2·F 1(P는 취득, F는 0학점).
- **남은 확인**: 학점포기 값의 실제 형태, 다른 과목 코드로 재수강한 경우(카탈로그 대응이 없으면 두 번 셀 수 있음), 계절학기 `SMT_NM` 이름(학기 해석 규칙이 여름·하계·겨울·동계를 읽음), 편입 인정 학점(`dsRcrdUnivRecgRecList`, 이번 학생 0행). 앱 창으로 보내 미리보기·추가·졸업 요건까지 이어지는 전체 흐름은 사용자가 본인 브라우저에서 확인한다(그 전까지는 단위 테스트와 이전 모의 포털 시험으로만 확인).

### 6-4. 연동 로드맵(2026-10-21 사용자 결정)

사용자 시험에서 북마클릿이 확인 창을 띄우지 못했다(원인 미확정). 그래서 연동을 세 단계로 나눈다. 판단 기준은 비밀번호를 넘기지 않을 것, 학교 화면이 바뀌어도 버틸 것, 학교를 넓히기 쉬울 것이다.

| 단계 | 방식 | 상태 |
|---|---|---|
| 1. 현재 | 학생이 성적증명서 PDF나 학점이수상황표 캡처를 올리고, 앱이 기기 안에서 읽는다(PDF는 글자 읽기, 캡처는 OCR) → 미리보기 → 추가 | 구현 전. 표본(증명서 PDF·학점이수상황표 캡처)이 필요하다 |
| 2. 1차 확장 | 학생이 로그인한 브라우저에서 코드 실행(브라우저 확장·앱 내장 브라우저). §6-3의 샘물 요청 구조를 다시 쓴다 | 북마클릿 시제품만 있음(§6-3) |
| 3. 최종 | 학교가 직접 보낸다(공식 API 또는 개인정보 전송요구권, 교육 분야는 2026-06-30~08-10 시행령 입법예고) | 시행 확정 전 |

- **1단계 근거**: 성적증명서는 모든 대학이 발급하는 문서라 양식이 학교 화면보다 덜 바뀌고, 학생이 자기 문서를 직접 올리므로 자동 접속도 비밀번호 수집도 없다. 2026-10-21 학교 허가를 받아 상명 샘물은 서버 대리 로그인으로 바꿨다(§6-5).
- **1단계 기술**: OCR은 상명프렌즈 앱(V44)에서 쓰던 PaddleOCR PP-OCRv5(검출 mobile 4.7MB + 한국어 인식 mobile 13.4MB, Apache-2.0)를 onnxruntime-web 1.22.0(wasm 11.2MB)으로 기기에서 돌리고, `ppocr.js`(이 프로젝트에서 작성)를 옮겨 온다. V44 표본 12장은 에브리타임 시간표 캡처라서 학점이수상황표 캡처로 다시 측정해야 한다. PDF 글자 읽기에는 pdf.js가 필요하다(새 의존성, 사용자 승인 전). 증명서 PDF에 글자 층이 있는지, 학수번호가 찍히는지는 확인하지 못했다.
- **표본 보관**: 실제 성적이 담긴 표본은 `private/`(git 제외)에만 두고, 테스트용 고정 데이터는 값을 바꾼 사본으로 만든다.

### 6-5. 샘물 서버 대리 로그인(2026-10-21, 학교 허가)

사용자가 상명대(상명프렌즈 융합혁신대학)의 공식 허가를 받아 학생이 넣은 학번·샘물 비밀번호로 서버가 대신 로그인하는 방식으로 바꿨다. 요청 주소·본문은 §6-3에서 실제 샘물 세션으로 확인한 구조를 따른다. 코드는 `api/smul.ts`(Vercel 함수, 다른 파일 import 없음). 새 저장소 P6에서 진입 파일만 남기고 `server/smul/`로 나눴다([0025](decisions/0025-smul-split-and-profile.md)).

```
화면(동의 필수, 학번·비밀번호) ─POST /api/smul─▶ api/smul.ts
  ① POST smsso.smu.ac.kr/Login.do (user_id, user_password) → 리다이렉트를 따라가며 쿠키 수집. 최종 주소가 Login.do면 401
  ② GET smul.smu.ac.kr/index.do (①의 쿠키) → 최종 주소가 https://smul.smu.ac.kr/ 가 아니면 423(로그인 5회 실패)
  ③ POST smul.smu.ac.kr/UsrRecMatt/list.do (②의 쿠키)
     본문 @d#=@d1#&@d1#tp=dm&_AUTH_MENU_KEY=usrCPsnlInfoUpd-STD&@d1#strStdNo=<학번>
     → dsRecMattList에서 년도·학기·학수번호·교과목명·이수구분·학점·성적만 남긴다
  ④ 이번 학기 수강 과목(2026-10-21 추가, 실패해도 ③은 보냄): 같은 메뉴 키로
     POST UsrSchMng/selectStdInfo.do (③과 같은 본문) → dsStdInfoList[0]의 CAMPUS_RCD·ORG_CLS_RCD만 읽음
     POST UcrTlsnAplyChk/onLoad.do → 기본 학년도·학기(_METADATA_), 학기 이름(dsSmtRcd)
     POST UcrTlsnAplyChk/list.do (dmParam, §6-3과 같은 값) → dsUcrTlsnAply에서 학수번호·교과목명·이수구분·학점만, '## <학기> 수강 중' 아래에
◀─ { rows } ── 미리보기(rowsToEnrollments) → 학생이 확인한 뒤 추가
```

- **저장·기록**: 학번·비밀번호는 함수 안에서만 쓰고 저장하지 않는다. 로그에는 실패 단계와 오류 이름만 남긴다. 응답은 `Cache-Control: no-store`. 화면은 비밀번호를 컴포넌트 상태에만 두고(localStorage에 넣지 않음) 받아 온 뒤 비운다.
- **검사**: POST만, `Origin` 호스트가 요청 호스트와 같을 때만, 학번 숫자 9자리·비밀번호 1~100자. 요청마다 10초 제한.
- **로그인 처리**: 리다이렉트 사이에 쿠키를 이름으로 넘기고(307·308이 아니면 GET), 브라우저 User-Agent를 보낸다. 최종 응답이 2xx가 아니면 상태 코드로 분류한다(2026-10-21 바꿈: 예전에는 모두 423 '비밀번호 장기 미변경'이었으나 근거가 없어 5xx·429·401/403 밖은 `UNKNOWN_UPSTREAM_ERROR`, 0013). 샘물 `ERRMSGINFO`가 오면 그 문구를 보인다(분류는 UNKNOWN).
- **이번 학기 수강 과목(2026-10-21)**: 사용자 시험에서 26-2 수강 과목이 들어오지 않았다. ③은 교과목이수확인 화면(`app/usr/usrSRecMatt`, 공개 화면 정의로 확인)의 요청이라 성적이 확정된 과목만 나온다. 그래서 §6-3에서 실제 세션으로 확인한 수강신청현황표 요청을 서버에서 부른다. 메뉴 키는 화면마다 다르지만(북마클릿은 `dsAllMenu`에서 찾음), 개인정보수정 키 하나로 ③이 응답하는 것을 사용자 시험으로 확인했으므로 학생 정보·수강신청현황에도 같은 키를 쓴다. **이 키로 수강신청현황표가 응답하는지는 실제 세션으로 확인하지 못했다.** 실패하면 로그 `smul current <오류>`가 남고 ③만 보낸다. 성공하면 `smul ok records=… noGrade=… current=…`(개수만)가 남는다. 성적이 이미 나온 과목(③에 같은 학기·학수번호가 있음)은 수강 중에서 뺀다.
- **뺀 것**: 교양영역(`CULT_ARA_NM`)은 값이 rules.json 영역 이름(`균형·인문` 등)과 같은지 확인 전이라 보내지 않는다(엔진은 기록의 영역을 카탈로그보다 우선하므로 이름이 다르면 영역 학점이 빠진다). F는 버리지 않는다(엔진이 미취득으로 처리). 이번 학기 수강 과목은 이 목록에 없다(사용자 시험).
- **북마클릿**: 2026-10-21 화면 재구성(§11)에서 코드까지 지웠다(`grab`·`bookmarklet`·`clipRows`). 요청 구조 기록은 §6-3에 남긴다.
- **학생 정보(2026-10-21)**: 응답에 `student: { name, dept, dept2 }`를 더했다. `selectStdInfo.do`의 `NM_KOR`·`TMP_DEPT_MJR_NM`(마지막 낱말)·`MJR_CD2`(마지막 낱말)만 읽고, 같은 행의 이메일·연락처는 버린다. 학과는 화면에서 `programs` 이름과 맞춰 고르고, 못 맞추면 학생이 고른다. `MJR_CD2` 값의 실제 형태(이름인지 코드인지)는 확인 불가.
- **SM-CDR 이수현황(2026-10-22)**: 같은 메뉴 키로 `POST UcdCdrCmpSch/list.do`(DataMap 둘: `dmParam` `strStdNo`·`strEntrSchYear`(빈 값), `dmPgmDiv` `strPgmDiv=ucdSCdrCmpSch`). 요청·열 이름은 공개 화면 정의 `/ui/app/ucd/ucdSCdrCmpSch.clx.js`와 `cleopatra.js`의 본문 규칙(DataMap마다 `@d1#`·`@d2#`)으로 확인했다. 응답 `cdr: { tracks, done }`은 `dsCdrAplyPcnd.CDR_NM`(신청 트랙)과 `dsNoSbjCmpPcnd`에서 `CMP_YN='Y'`인 `PGM_NM`(이수한 비교과, 화면도 이 값으로 개수를 셈)만 담는다. 실패해도 수강 기록은 보내고 로그 `smul cdr <오류>`만 남는다. **실제 샘물 세션에서 이 메뉴 키로 응답하는지, `CDR_NM`이 `programs` 이름과 같은 꼴인지는 확인 불가**(못 맞추면 트랙은 학생이 고른다). 엔진은 `Profile.done`(이수한 비교과 이름, 띄어쓰기 무시)과 각 트랙 `ex.list`가 겹치는 개수로 판정하므로, 한 프로그램이 그 이름이 든 모든 트랙에 함께 들어간다.
- **휴학 추정(2026-10-22)**: 가져오기 저장 때 입학 학기~현재 학기 전 정규학기 중 수강 기록이 없는 학기를 휴학으로 넣는다(`src/paste.ts` `guessLeaves`, 직접 넣은 휴학·편입생은 건드리지 않음). 엔진은 현재 학기가 학기 목록에 없으면(휴학 미입력으로 8학기가 먼저 끝남) 현재 학기까지를 지난 학기로 보고 추천하지 않는다(예전에는 처음 학기부터 다시 추천했다). 샘물 학적 변동 기록은 아직 받지 않는다.
- **개발 서버**: `vite.config.ts`의 `local-api` 미들웨어가 같은 함수를 `/api/smul`에 붙인다. 개발 서버와 `vite preview`(빌드본) 둘 다(2026-10-21, 미리보기에 없어서 404가 났던 것을 고침).
- **이수구분 판정 기준(2026-10-22)**: 이수구분은 수강 당시 기준으로 학교가 기록한 값을 쓴다. 샘물에서 가져온 과목은 교과목이수확인(`dsRecMattList.CMP_DIV_NM`)·수강신청현황(`CMP_DIV_NM`) 값이 카탈로그보다 우선하고(`Enrollment.category`), 직접 넣은 과목은 수강한 해의 교육과정 판에서 읽는다(`policy.edition: 'term'`). 그래서 지금 교육과정에서 이수구분이 바뀐 과목도 당시 값으로 판정된다. 대조용으로 학점이수상황표(`ugdSCdtTable`, 공개 화면 정의로 요청·열 이름 확인) `POST UgdCdtTable/list.do`(`dmParam` `strStdNo`·`strStdNm`(빈 값)·`strCampusRcd`)의 '이수구분별 취득학점'(`dsCmpDivRecList` `CMP_DIV_NM`·`GET_CDT`)을 받아 `cmp`로 보낸다. 이 화면에는 과목별 목록이 교양에만 있어 합계만 쓴다. 학점 계산기 '확인할 점'에 성적이 나온 기록의 이수구분별 합계(`engine/audit.ts` `cmpDiff`, F·재수강 이전·중복·수강 중 제외)가 학교 값과 다른 이수구분을 보인다. 판정 자체를 학교 합계로 덮지는 않는다(어느 과목이 바뀌었는지 알 수 없다). **실제 학생 계정으로 확인(2026-10-22, 2022학번 1명, 값은 기록하지 않음)**: 이 메뉴 키로 응답했고 이수구분 5개(1전선·1전심·교선·교필·일선)의 학교 합계가 앱 합계와 모두 같았다(대조 경고 0건, F는 학교도 빼고 셈). 이 학생은 성적표 이수구분과 졸업 판정 이수구분이 다른 과목이 없었다. 이수구분이 실제로 바뀐 학생의 경우는 아직 확인하지 못했다. 실패하면 로그 `smul cmp <오류>`만 남는다.
- **확인한 것**: 가짜 샘물로 요청 순서·쿠키 전달·본문·열 걸러내기·401·출처/학번 검사(`src/smul.test.ts`). 개발 서버에서 400·405 응답. 화면에서 동의 → 입력 → (가짜 응답) → 미리보기 → 추가, 오류 표시, 375px 레이아웃.
- **확인 불가**: 실제 샘물 로그인(학생 본인 계정 필요), Vercel 배포 빌드(TypeScript 함수 컴파일), 실제 `SMT_NM` 값과 학점포기·편입 인정 행의 형태.
- **남용 방어(2026-10-21 사용자 결정, `docs/handoff/2026-10-21-smul-security.md`)**: Vercel 방화벽 규칙은 쓰지 않고 함수 안에서 센다(`api/smul.ts` `limit`). 샘물에 요청하기 **전에** Supabase RPC `smul_try`로 횟수를 원자적으로 올려(동시 요청도 하나씩) **IP 1분 10회**, **학번 1시간 3회**(샘물 5회 잠금 전에 멈춤)를 넘으면 429. IP에서 막힌 요청은 학번 횟수를 올리지 않는다. 가져오기에 성공하면 `smul_ok`로 학번 기록을 지운다.
  - 2차 보강(레퍼런스 비교 뒤 채택, `docs/decisions/0010`): **서비스 전체 차단기**(10분 창에서 샘물로 나간 호출의 실패율 50% 이상·최소 20회면 모든 중계를 멈추고 503, Resilience4j 기본 실패율), **IP당 하루 로그인 실패 100회**(401·423만 셈, 넘으면 429, Auth0 IP 제한 예시 값). 검사 전에 표를 한 번 읽어(`GET /rest/v1/smul_try?k=in.(…)&until=gt.…`) 두 조건을 보고, 결과에 따라 `all:f`·IP 하루 키를 올린다. 걸리면 `smul breaker open`·`smul ip day limit` 로그를 남긴다.
  - **3차(2026-10-21, 사용자 정책, `docs/decisions/0013`)**: 위 학번 1시간 3회·IP 하루 100회·'200이 아니면 실패' 차단기를 바꿨다.
    - 실패 분류 `Kind` 8가지(`AUTH_REJECTED`·`ACCOUNT_LOCKED`·`UPSTREAM_TIMEOUT`·`UPSTREAM_CONNECTION_ERROR`·`UPSTREAM_SERVER_ERROR`·`UPSTREAM_RATE_LIMITED`·`AUTHORIZATION_OR_ACCESS_BLOCK`·`UNKNOWN_UPSTREAM_ERROR`). 실패마다 `smul fail <분류> <상태>` 로그.
    - 전체 차단기는 시스템 장애(시간 초과·연결·5xx·429)만 센다. 분모 = 성공 + 시스템 장애(비밀번호 오류·잠김·UNKNOWN·접근 거부는 분자·분모 모두 제외, UNKNOWN·접근 거부는 `all:unk`·`all:blk`로 따로 셈). 10분 창 `all:ok:<창>`·`all:sys:<창>`. 장애 5회·20% 이상이거나 샘물 429면 **줄임**(전체 1분 20회·동시 2개), 20회·50% 이상이면 **열림**(5분, 1시간 안 재열림은 두 배·최대 10분), 대기 뒤 **반쯤 열림**(한 번에 하나, 먼저 비밀번호 없는 `GET https://smul.smu.ac.kr/` 시험, 성공 2번이면 닫고 10분 줄임). 상태는 표 행 `brk:open`·`brk:half`·`brk:ramp`·`brk:trips`·`brk:ok`, 동시 자리는 `slot:<i>`.
    - IP: 최근 24시간(1시간 칸 24개 `HMAC('ipf:'+IP):<시>`) 로그인 실패 50회면 그 IP만 429. 1분 10회는 그대로. `x-forwarded-for`는 `VERCEL`일 때만 믿는다.
    - 학번: 한 번에 하나(`idl:` 자리, 60초 만료), 로그인 실패 k번째 뒤 대기 30초·1분·(3번째부터) 15분(`idw:`), 실패 수 1일(`idf:`), 성공 시 삭제. 키는 `HMAC('id:'+학번)` 앞에 접두사.
    - 서버·화면 모두 자동 재시도 없음(로그인 재시도는 비밀번호를 다시 내는 것).
    - 값은 `api/smul.ts` `LIMIT` 한 곳(초기 후보, 이용량 확인 불가). 마이그레이션 변경 없음.
    - 한계: 남이 한 학번을 노리면 약 31분 만에 샘물 5회 잠금에 닿을 수 있다(전에는 약 1시간). 여러 IP 스프레이는 차단기를 열지 않는다. 공유 와이파이는 IP 하나로 묶인다.
  - 키: `HMAC-SHA256(SMUL_KEY_SECRET, 'ip:'+IP | 'id:'+학번)` 16진수. 학번은 10⁹가지라 그냥 해시는 되돌릴 수 있어서 서버 비밀값을 쓴다. IP는 `x-forwarded-for` 첫 값(Vercel이 덮어써 위조 불가, 공식 문서).
  - 저장소: Supabase `credit-planner` 표 `smul_try(k, n, until)`, 마이그레이션 `supabase/migrations/20261021131227_smul_try.sql`(적용됨). RLS on·정책 없음, 함수는 `security definer`이고 실행 권한은 service_role만(공개 키로 부르면 401 `permission denied` 확인). 만료된 행은 `smul_try`를 부를 때 지운다.
  - 환경변수(Vercel 서버 전용): `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`(새 `sb_secret_` 키나 예전 service_role 키, `apikey` 헤더로만 보냄), `SMUL_KEY_SECRET`(충분히 긴 임의 문자열). 셋 중 하나라도 없으면 로컬 개발에서는 제한을 건너뛰고, Vercel(`VERCEL` 있음)에서는 503. Supabase가 응답하지 않아도(3초) 503 — 학생 계정 잠금 방지를 먼저 둔다.
  - 한계: 남이 3번 틀리면 그 학번은 최대 1시간 이 서비스를 못 쓴다. 같은 와이파이 학생들은 한 IP로 묶인다. 샘물 실패 횟수가 시간이 지나도 쌓이는지는 확인 불가(쌓인다면 느린 대입으로 잠금 가능).
  - 개인정보 안내(`TERMS`)에 시도 횟수 기록(HMAC 값, 항목별 기한, 성공 시 삭제)과 서버 로그 항목(단계·오류 종류·건수, 학번·비밀번호·IP 없음)을 적었다(3차에서 갱신). Vercel 런타임 로그 보관 기간은 공식 문서 검색으로 찾지 못해 확인 불가. 시험: `src/smul.test.ts`(가짜 Supabase로 학번 3회·IP 10회·성공 시 삭제·원문 미전송·저장소 장애·설정 누락).
- **남은 일**: Vercel 환경변수 세 개 설정(배포 때). 허가 범위(샘물 운영 부서 포함 여부)와 허가 문서 보관. 2단계 `/api/join`·`/api/reset`도 같은 `limit`을 거친다.

## 8. 미확인·위험

- **학생 기록은 샘물 값이 정답이다(2026-10-27, §12)**: 과목·학수번호·이수구분·학점은 샘물에서 그대로 받으므로 카탈로그와의 대조·[미확인] 표시는 뺐다. 앱이 직접 가진 값은 졸업 기준(필요 학점·영역 기준·SM-CDR 3/30/2/1)뿐이고, 이것은 매년 3월 1일 갱신한다(§5). 편입생·유학생 요건은 데이터가 없어 `ok:null`(확인 필요)로 남는다. 편입생·다전공 학생 실사용 대조는 사용자가 진행할 예정이다.
- **외부 대학 데이터는 AI가 작성했고 사람 검토 전이다.** 충남대 졸업이수학점표의 6·6·2 세 열 의미 미확정, 성적표 이수구분 명칭, 연세 채플 경감·편입 인정 원문 미열람.
- **성적표 형식**: 대학별로 이수구분이 성적표에 찍히는지는 확인이 필요하다.
- **명칭·법률**: '수뭉이'는 학교 캐릭터일 가능성이 있어 이름을 바꾼다. 대학명 사용, 공개 페이지 수집의 이용약관·DB권, 포털 연동 방식은 법률 검토가 필요하다(확인 불가).
- **모바일**: Capacitor 웹뷰에서 HiGHS WASM·OCR 성능, App Store 4.2(최소 기능) 심사는 모바일 단계 전에 시험한다.
- **기존 사용자 이전**: 출처가 달라 아티팩트 localStorage는 읽을 수 없다. 백업 파일 가져오기(`engine/fromLegacy.ts`)만 가능하다.

**구성**: Vite 8.3.2 + React 19.3.0 + TypeScript 7.0.2(타입 검사만). 라우터·상태관리 라이브러리 없이 `useReducer` + 해시 탭(`#/profile` `#/records` `#/audit` `#/plan`). `@vitejs/plugin-react`는 넣지 않았다(Fast Refresh만 잃고 JSX는 Vite 내장 변환). 레이아웃은 `docs/wireframe.html`(의존성 없는 와이어프레임)에서 확정한 뒤 옮겼다: 왼쪽 사이드바(데스크톱 펼침 ↔ 아이콘 레일, 모바일 서랍), 미끄러지는 선택 표시, 네이티브 `<dialog>` 설정, `prefers-reduced-motion` 존중.

**흐름**
- 데이터: `src/data.ts`가 `import.meta.glob`으로 `data/<univ>/` 파일을 자산으로 내보내고, 고른 대학의 `rules.json`·`sets.csv` → `assemble()`, 고른 프로그램의 카탈로그만 내려받는다. 대학 목록은 `rules.json`의 `name`만 번들에 들어간다.
- 졸업 요건: 화면 스레드에서 `audit()`(수 ms). 결과 트리에 충족/들으면 충족/부족/확인 필요(`ok:null`)를 보인다. (2026-10-27 미확인 기준 `unverified` 표시는 뺐다, §12)
- 추천: `src/plan.worker.ts`(Web Worker, ES 모듈)에서 `plan()`. `engine/plan.ts`에 `initHighs({ locateFile })`를 추가해 Worker가 빌드된 `highs.wasm` URL을 넘긴다(Node는 기존처럼 바로 불러옴). 결과의 `after.items`(Set·카탈로그 참조)는 보내지 않는다.
- 입력: 학교 사이트(§6-1), 카탈로그 검색(`<datalist>`), 직접 입력(편입 인정 일괄·학점교류 출처 포함), 성적표 붙여넣기(`src/paste.ts`: HTML 표/탭 텍스트 → 머리글로 열 찾기 → 미리보기), 이 앱 백업 JSON, 상명 앱 저장 상태(`fromLegacy`).
- 저장: `localStorage['credit-planner.v1']`. 서버에 저장하지 않는다(샘물 가져오기만 `api/smul.ts`를 거친다, §6-5). 백업은 파일 내보내기/가져오기.
- 오류 신고: 대학·프로그램·연도·규칙 id만 담는다. `VITE_REPORT_URL`(예: 이슈 생성 URL)이 있으면 그 주소로 열고, 없으면 신고 문구를 클립보드에 복사한다.

**확인한 것**: `npm run build`(tsc + vite build) 통과, `npm test` 통과(엔진 V1~V4·데이터 검사 + 붙여넣기 파서). 내장 브라우저에서 개발 서버와 빌드본(`vite preview`) 둘 다로 상명 천안 소프트웨어학과 2023(붙여넣기 35과목 → 판정 → 추천 최적해, 계절학기 켜기/끄기, 상명 앱 저장 상태 가져오기)과 연세대 컴퓨터과학과 2026(검색·붙여넣기 → 판정 → 추천 최적해)을 확인했다. 데스크톱·레일·모바일(375px) 서랍·설정 창·다크 테마 확인.

**남은 일**
1. **오류 신고 수신처 결정**: `VITE_REPORT_URL` 값(이슈 트래커·폼)이 정해지지 않았다.
2. **학교 사이트 가져오기 실제 화면 검증**(§6-1·§6-3): 샘물은 확인·구현 완료(한 번에 가져오기). 남은 것은 §6-3 '남은 확인'과 연세·충남 포털. 에브리타임은 이용 허락을 받을 때까지 보류.
3. **상명 앱 데이터 꺼내는 방법**: V44 소스에서 파일 내보내기 기능을 찾지 못했다. 가져오기는 저장 상태 객체(S) JSON을 받는데, 실제 사용자가 그 JSON을 얻는 경로는 확인 불가. 현재 앱에 내보내기 버튼을 추가하거나 안내가 필요하다.
4. **붙여넣기 실제 포털 검증**: 머리글 이름 규칙(`학수번호`·`교과목명`·`이수구분`·`학점`·`년도`·`학기` 등)만으로 만들었고 실제 샘물·연세 포털 표로는 시험하지 않았다(확인 불가). 포털 fixture가 생기면 `src/paste.test.ts`에 추가한다.
5. **데이터 쪽 일반화**: 트랙 소속은 id 규칙(`cdr.<학과>.<번호>`)으로 찾고, 다전공·부전공은 상명의 `ext` 프로그램에만 연결된다. 다른 대학에 트랙·다전공 데이터가 생기면 `programs`에 소속·역할 필드를 둔다. 연세·충남은 교양 카탈로그가 없어 교양 요건은 추천에서 '데이터로 채울 수 없음'으로 나온다.
6. **편입생 첫 학기**: 입학년도를 편입한 해로 보고 5학기부터 센다(`startTerm` 입력 없음).
7. **성능·용량**: 첫 추천 때 `highs.wasm` 3.5MB(gzip 1.2MB)를 받는다. 추천마다 Univ 전체(상명 `rules.json` 567KB)를 Worker로 복사한다. 느리면 Worker 쪽 캐시.
8. **브라우저 호환**: Chrome 계열(내장 브라우저)에서만 확인했다. Safari·Firefox는 확인 불가. 판정 트리 펼침 애니메이션(`::details-content`)은 지원 브라우저에서만 움직이고 나머지는 애니메이션 없이 열린다.
9. **UI 자동 테스트 없음**: 화면 흐름은 수동 확인만 했다. 배포 전에 판정·추천 한 경로씩 브라우저 테스트를 둔다.
10. 이후 단계는 §9 그대로: 정적 배포, OCR 이식, 샘물 추출기, 외부 대학 정식 입력.

## 11. 상명대 천안캠 전용 화면 재구성 (2026-10-21)

범위를 상명대 천안캠퍼스로 줄이고, 상명대학교 UI(시그니처 로고·SM Blue `#0E207F`·천안캠 사진)를 바탕으로 사용자가 구상한 화면(상단 메뉴 + 사진 배너 + 흰 본문)으로 바꿨다. 설계는 `docs/superpowers/specs/2026-10-21-smu-cheonan-redesign-design.md`, 와이어프레임은 `docs/wireframe-smu.html`. 이번은 1단계(화면)이고, 2단계(회원제·Supabase 서버 저장)는 설계 문서 §4.

- **화면**: 해시 `#/`(홈) `#/join`(샘물 가져오기) `#/result`(졸업요건) `#/plan`(학기추천) `#/my`(마이페이지) `#/terms`(이용안내). 상단 메뉴에 샘물에서 받은 이름(`{이름}님`)을 띄운다. 사이드바·설정 창·다크 테마·대학 선택은 뺐다(테마는 밝은 화면만).
- **데이터 범위**: `src/data.ts`의 glob을 `data/smu-cheonan/`으로 좁혀 다른 대학은 번들에 들어가지 않는다. 저장된 상태의 `me.univ`는 불러올 때 상명 천안으로 고정한다.
- **입력 경로**: 샘물 가져오기, 과목 검색, 직접 입력만 남겼다. 붙여넣기·북마클릿·백업 내보내기/가져오기(상명프렌즈 JSON 포함)는 코드까지 지웠다(`engine/fromLegacy.ts`는 엔진 쪽이라 남김). 다시 가져오면 샘물 기록으로 바꾸되 편입·학점교류 인정과 다음 학기 이후 계획은 남긴다.
- **졸업요건 요약**: 주전공 결과에서 규칙 id `total`·`major`·`ge`·`ext`를 찾아 졸업 기준·총 이수·전공·교양·다전공을 보이고, 일반 = 총 이수 − 전공 − 교양 − 다전공(0 이상, 전공심화는 전공에 포함). 카드는 `primary`·`gearea`·라벨 없는 묶음을 한 단계 풀어 만든다(상명 천안 데이터 기준, `src/pages.tsx` `cardsOf`).
- **요건별 과목**: 엔진 `Result`에 `used`(셈에 들어간 기록 번호, credits·courses만)를 더했다. 모달은 요건 트리와 들어간 과목 표를 보여 준다. 아직 안 들은 필수 과목 목록은 엔진이 내지 않으므로 학기추천으로 안내한다.
- **자산·보안 헤더**: `public/logo.jpg`(smu.ac.kr UI 시그니처 type1, 가로 420px), `public/campus.jpg`(smu.ac.kr 상명 갤러리 '천안캠퍼스 여름 스케치' 2023, 1920px). 글꼴 Noto Sans KR(Google Fonts) 때문에 CSP에 `style-src https://fonts.googleapis.com`, `font-src https://fonts.gstatic.com`을 더했다.
- **확인한 것**: `npm run build` 통과, `npm test` 통과. 개발 서버에서 `/api/smul` 응답만 가짜로 바꿔 동의 → 학번·비밀번호 → 확인(학과 자동 맞춤·입학년도) → 저장 → 졸업요건(요약·카드·모달) → 학기추천 → 마이페이지(과목 추가 모달)를 1280px·375px에서 확인했다. 빌드본(`vite preview`, 배포와 같은 CSP)에서 로고·사진·글꼴이 오류 없이 뜬다.
- **확인 불가**: 실제 샘물 계정으로 가져오기(학생 본인 계정 필요), Safari·Firefox.

**같은 날 추가 수정**
- 메뉴 이름: 졸업요건 → **학점 계산기**, 학기추천 → **학점 플래너**.
- 마이페이지 '정보 수정'(펼침): 단과대학 → 학과 순서로 고른다. 단과대는 V44 `units.json`의 `college`를 `etl/smu-cheonan/migrate.ts`가 `rules.json` `programs[*].college`로 옮긴 값(5개 단과대·40개 학과, 다른 값은 그대로임을 비교로 확인). 직접 입력 항목도 같은 펼침.
- 학점 계산기: 평점·포트폴리오 같은 직접 입력 항목을 카드 안에서 바로 넣고(숫자 칸·스위치), 진로 트랙(SM-CDR)을 카드에서 고른다(고른 트랙은 학점 플래너 `opts.tracks`와 같은 값). 트랙 '자세히'에 트랙 인증 항목 입력을 붙였다.
- 학점 플래너 바꾸기(V44 '바꾸기 칩'과 같은 기능): `plan()`이 `alts['학기|학수번호']`를 함께 낸다. 후보 조건은 추천 과목이 채우는 요건 칸(졸업 학점 제외)을 모두 채우고, 학점이 같거나 많고, 그 학기에 들을 수 있고, 학기 상한을 넘지 않을 것. 그래서 바꿔도 부족분이 늘지 않는다(`engine/v5.swap.test.ts`). 고른 바꾸기는 `state.swaps`에 저장하고 화면에서 추천 행에 덮어쓴다(지금 계획에 없는 바꾸기는 무시, '처음 추천으로 되돌리기').

**학점 계산기 설명 보강(2026-10-21, 사용자 선택 A·C. B '남은 할 일' 목록은 만들었다가 사용자 요청으로 뺐다)**
- A. 카드마다 인정 기준 한 줄: 결과 트리와 규칙 트리를 나란히 따라가(`ruleAt`) 규칙의 `hint`가 있으면 그것을, 없으면 필터에서 만든다(태그 → `categories`의 이수구분, `every` → `areas`의 교양 영역, codes·names → 지정 과목 수, 묶음 → 하위 라벨). 학점 칸은 들어간 학점을 이수구분별로 보인다(예: 1전선 3 + 1전심 6).
- C. 자세히 창의 '채울 수 있는 추천 과목': 학점 계산기 화면에서도 같은 옵션으로 추천을 풀고(Worker), 추천 행의 `keys`('프로그램.요건 id', `plan()`이 함께 냄)가 카드 요건 하위에 들어가는 것만 보인다. 바꾸기(`state.swaps`)를 반영한다. 주전공과 진로 트랙에 같은 id(`deep` 등)가 있어 id만으로 거르지 않는다.

**화면 다듬기(2026-10-21)**
- 학점 계산기의 '자세히' 창을 없애고 카드를 눌러 그 자리에서 펼친다(펼친 카드는 한 줄 전체). 진로 트랙 카드는 펼침 안에 트랙별 기준·인증 항목 입력. 요약 제목은 '학과 학번 이름'.
- 학점 플래너: 추천 과목마다 '⇄ n'(바꿀 수 있는 후보 수)·'고정'(대신할 과목 없음: 지정 과목·다른 후보가 이미 계획에 있음·학기 상한)·'넣어 둔 과목' 표시와 범례.
- 마이페이지 '기이수 과목' → '이수 과목'.
- 샘물 가져오기 보안·방화벽은 다른 세션으로 넘긴다: `docs/handoff/2026-10-21-smul-security.md`.

## 12. 샘물 기준 정리·배포 준비 (2026-10-27)

**샘물 값을 정답으로(ADR 0016)**. 사용자 결정: 샘물은 학교 공식 시스템이라 학생 기록은 샘물 값이 가장 정확하다. 실사용 대조는 사용자 동기들로 했다(값은 기록하지 않음).
- 요건 칸의 '미확인 기준' 표시와 규칙의 `unverified` 필드를 엔진(`Rule`·`Result`)·화면·데이터(상명·연세·충남 `rules.json`)·`migrate.ts`에서 뺐다. `sets.csv` 근거 문구의 `[미확인]`도 뺐다.
- 학점 계산기 '확인할 점'의 '미등록 학수번호'(카탈로그에 없는 학수번호) 경고를 뺐다(`engine/audit.ts` `resolve`). 그런 과목도 샘물의 과목명·이수구분·학점으로 그대로 센다.
- 가져오기 확인 화면에서 학수번호 없는 행을 카탈로그 과목명으로 채우던 `fillCodes`와 '학수번호도 학점도 모르는 과목' 경고를 지웠다. 샘물 응답(`api/smul.ts` `toRows`)은 이수 기록·수강 중 과목 모두 `SBJ_NO`를 준다.
- 남긴 것: 카탈로그는 학점 플래너 추천·'아직 안 들은 관련 과목'·과목 검색에 계속 쓴다. 학교 이수구분별 합계와 앱 합계가 다를 때의 '확인할 점'(`cmpDiff`)과 '대응표에 없는 이수구분' 경고는 샘물 값과의 차이를 알리는 것이라 남겼다.
- 범위 밖: 시간표(겹침)는 수강신청 앱이 아니라서 다루지 않는다. 플래너 추천을 실제 시간표에 맞추는 것은 학생이 한다.

**배포: Vercel + Supabase, 프로젝트 이름 `grad-planner`(ADR 0006 갱신)**
- Vercel 프로젝트 이름은 소문자만 되므로 `grad-planner`. `package.json` `name`도 맞췄다. 함수 리전 `icn1`, 보안 헤더는 `vercel.json` 그대로.
- Supabase는 기존 서울 프로젝트(ref `chkmaephrtufzbktigfx`)를 쓴다. 마이그레이션 `smul_try` 적용 확인(2026-10-27). 보안 권고는 `smul_try` 'RLS 켜짐·정책 없음'(INFO) 하나이고, service role만 쓰도록 일부러 그렇게 둔 것이다.
- Vercel 환경 변수(Production): `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SMUL_KEY_SECRET`(임의 긴 문자열). 없으면 `/api/smul`은 Vercel에서 503으로 막힌다. 선택: `VITE_REPORT_URL`.

**학적·졸업 기준도 샘물 값으로(2026-10-27, 사용자 결정 "표시되는 정보 전부 샘물에서", ADR 0016 갱신)**

- 학생 정보(`api/smul.ts` `student`): 입학구분 `ENTR_RCD_NM`, 다전공 `MJR_CD2~4`(2~4전공)·`MJR_CD_B1/B2`(부전공)·`CONN_MJR_CD_1/2`(연계)·`FUSE_MJR_1/2`(융합)·`MICRO_MJR_1~3`(마이크로전공), 유학생 여부(`NAT_RCD_NM`이 한국이 아니면 true, 국적 값은 내보내지 않음). 로그 `smul ok`에 입학구분 이름과 다전공 종류만 남긴다.
- 전적대학 인정학점(`recg`): `POST UgdAllRecSch/list.do`(`dmParam` 학번·이름(빈 값)·조직 코드, 같은 메뉴 키) → 이수구분별 학점. 화면은 `전적대학 인정(<이수구분>)` 일괄 기록(`src:'transfer'`, `lump`)으로 넣고, 다시 가져오면 예전 편입 인정 기록을 바꾼다.
- 학적은 샘물 값으로 정한다: 입학구분에 '편입'이 있으면 편입생, 2~4전공·연계·융합이 있으면 다전공(복수전공 기준), 부전공만 있으면 부전공, 마이크로전공은 학점 기준을 바꾸지 않는다. 샘물에서 가져온 학생은 마이페이지에서 입학년도·이수 형태·입학 유형·학생 유형을 고칠 수 없다.
- 졸업 학점 기준(`Profile.vars`, `src/pages.tsx` `baseVars`): 학교 기준학점 열을 세트 숫자로 덮어쓴다. 단일 `GRDT_CMP_CDT`→total·`CULT_CDT`→ge·`MJR_CDT`→major·`MJR_DEEP_CDT`→deep, 다전공 `MMJR_MAIN_MJR_CDT`→major·`MMJR_MJR_CDT`→ext, 부전공 `MINOR_MAIN_MJR_CDT`→major·`MINOR_MJR_CDT`→ext. 세트에 있는 이름만 덮어쓰고(`pickSet`), 주전공에만 적용한다. 평점 기준(`GP_AVG`)·교양 필수 영역·SM-CDR 기준은 아직 데이터 값이다.
- 편입생: 학교 기준학점은 학생별(입학구분 포함)이라 편입생 기준이 그대로 들어온다. 상명 데이터에는 편입생 세트가 없어 그동안 신입 세트로 판정됐다(ADR 0016의 'ok:null' 서술과 달랐음). 이제 신입 세트를 쓸 때 `policy.transferUnknown`(상명: `gearea`)의 교양 필수 영역은 '편입생 기준 확인 필요' 입력 항목(ok:null)으로 바뀐다. 학교 공개 자료에서 상명 천안 편입생 교양 영역 기준은 찾지 못했다(웹 검색 2026-10-27).
